## 4. 關鍵發現與正確解讀

**推薦數變少不代表模型變差，應視為「篩選變精準」。** 加入具體、可驗證的條件（資歷、證照、技能）讓候選人池收斂到更貼合需求的範圍，是正常且期待中的行為：

| 補充文字類型 | vs 純 URL | 解讀 |
| :--- | :--- | :--- |
| 資歷／經驗、語言／證照、純技能 | -0.9 ～ -0.1 | **精準篩選**：具體可驗證條件讓結果小幅收斂，符合預期 |
| 軟性偏好、混寫 | +2.1 ～ -0.4 | 接近持平 |
| 明講性別年齡 | +4.9 | 沒有收斂，反而變寬 |
| 暗示性別年齡 | **+16.0** | 完全沒有收斂、還大幅擴張 |

真正該關注的不是「數字增減」本身，而是這個對比揭露的行為差異：

1. **技能／證照這類「有實際篩選價值」的文字讓結果收斂**——模型運作符合預期。
2. **性別年齡這類文字（尤其暗示性的）卻讓結果不減反增，且幅度是明講歧視語句的 3 倍以上**——代表模型沒有把這些詞當作篩選條件在處理，而是當成某種泛用的相關性訊號在放大匹配範圍。
3. **補充文字 100% 原樣寫入 `query_used`，無任何過濾或改寫**（S2 全部 7 組 passthrough rate 皆為 1.0）。

三點合起來，比單純說「模型會歧視」更精確的結論是：**模型無法區分「有效篩選字詞」與「身份標籤字詞」，對後者的處理方式明顯偏離對合規篩選條件的處理邏輯**——這是需要往回報給後端／產品端確認的實際風險，而非測試框架本身的缺陷。
