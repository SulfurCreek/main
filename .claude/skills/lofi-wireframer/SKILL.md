# Balsamiq 風格 Lo-Fi Wireframer

把輸入（截圖、需求描述、既有頁面結構）轉成極簡的手繪風 HTML wireframe，聚焦「結構、使用者流程、系統邏輯」，
不呈現任何視覺設計細節。

## 核心輸出限制

- 輸出**單一自包含的 `index.html`**（Tailwind CSS 走 CDN 引入）。
- **只輸出程式碼**，不要輸出 markdown 說明文字。

## 1. Balsamiq 手繪風美學

- **字體**：全域套用 Google Fonts 的 `Caveat`，模擬手寫感。
- **色彩**：只准黑、白、淺灰三色，去除所有品牌色。
- **邊框**：所有容器與輸入框一律 `border-2 border-black`。
- **圖片**：一律用以下佔位方塊取代真實圖片：
  ```html
  <div class="bg-gray-200 border-2 border-black flex items-center justify-center text-gray-500 font-bold text-2xl">X</div>
  ```
- **文字**：長段落一律用結構性方括號取代，例如 `[ 系統狀態說明放這裡 ]`。

## 2. 註記與流程系統

- **版面**：強制 2 欄式版面。左側放主線框圖，右側固定保留 300px 側欄作為「Technical Specs & Flow Logic」。
- **編號徽章**：在線框圖中互動元件上疊加醒目的小型編號徽章。
- **側邊便利貼**：右側側欄對應每個編號建立便利貼樣式的說明區塊：
  ```html
  <div class="bg-yellow-100 border border-yellow-400 p-3 mb-4 text-sm">…</div>
  ```
- **便利貼內容**：用來說明資料庫邏輯、使用者狀態、技術限制，例如「外部使用者連續 3 次登入失敗後觸發安全冷卻狀態」。

## 3. 執行方式

1. 分析輸入內容的核心版面結構。
2. 依上述美學規則轉成 lo-fi 版本。
3. 把任何功能性邏輯（狀態機、資料庫欄位、觸發條件等）抽取到右側註記側欄，並用編號徽章對應連結。

## 4. 反向工程模式（真實畫面截圖＋規格書 → 異動區塊線框圖）

當輸入是**已存在的真實 UI 截圖**加規格書（例：E3.2.0「未讀」篩選，產出在 `handoff/wireframes/E320_unread/`），
改用本節規則；與 §1 衝突時**以本節為準**（不用 Caveat、不用 X 佔位方塊，保持真實版面）。

### 4.1 版面與灰階
- 以真實畫面寬度為基準（例：1182px = 截圖 2364px @2x），**整張灰階，但不用 CSS filter**（濾鏡無法被子元素取消，會讓便利貼變灰）：圖片預先轉灰階、CSS 色票改灰色，見 §4.3。
- **未異動區塊用真實截圖裁切**（`background:url(...) / <實寬>px`），**只重畫有異動的區塊**；不要整頁重畫。
- 裁切圖前先轉灰階存檔（Pillow `convert('L')`），透明區先合成到畫面底色 `#F0F0F0`。
- 要蓋掉截圖內的舊元件（如 tag 列）時，用同位置白底 cover 疊上重畫版，位置以渲染後截圖比對校正（偏差 ≤2px）。

### 4.2 圖片來源（踩過的坑）
- **相對路徑 `assets/…` 會在使用者端失效**（檔案單獨開啟／預覽窗找不到資料夾 → 區塊變白底）。
- **最終交付的 `index.html` 必須自包含、可單檔下載**：圖片以 base64 data URI 內嵌（單張 <200KB 可行）；不依賴 Tailwind CDN（只用到幾個樣式就自己寫進 `<style>`），字體 CDN 可有但要有 fallback。交付時直接用 SendUserFile 傳這一個檔。外部 R2 網址也可能被預覽環境擋，不當唯一來源。
- 圖片仍依 `photo` skill 規則上傳 R2（key 前綴 `photo-skill/`，憑證只讀環境變數）供 HackMD 嵌圖；R2 用途是「各狀態輸出 PNG」，不是 HTML 的載圖來源。
- 使用者給的新截圖（R2 網址）先 `curl` 下載到 scratchpad、確認尺寸與內容再裁切。

### 4.3 表達方式（UI/UX 階段，不是規格書）
- **frame 以「情境」命名**，用使用者動作／畫面狀態描述（例：「履歷狀態選『未讀』」「這一頁全部都是已讀（後面還有其他頁）」），**不要用 S1、S2… 編號**，也不要在副標列一串狀態值。
- **初始／現況畫面不畫**：沒有異動的預設狀態不需要一張 frame，**從本次需求的起點開始**。
- **畫面上不放規格書代碼**（2.2、3.1a、3.3~3.7、空畫面 b、區塊 4／5…）。代碼是規格文件與 Claude 對照用，線框圖只要用**虛線框**把有異動的區塊框起來（`outline:2px dashed`）。側欄、便利貼、對照表的文字也改用白話（「摘要文字」「多筆操作」「分頁」），不寫代碼。
- **便利貼直接貼在對應位置**，不集中在右側欄：每張便利貼綁一個錨點元件（`data-a`，錨點設 `position:relative`），**把便利貼 append 成錨點的子元素**，用 CSS（`left:calc(100% + 14px)` 等）相對錨點定位，再用 dx/dy 微調。**不要用 JS 量 `getBoundingClientRect` 算絕對座標**——字體、視窗寬度不同時座標會漂移，使用者看到的就是「便利貼浮動」。便利貼需自行設 `white-space:normal`（錨點常是 nowrap），壓在未異動的卡片上可以接受。
- 兩種便利貼：黃底＝規則說明；**橘色虛線＝待確認**（文件未定義，圖中不自行決定）。畫面上找不到對應位置的待確認項，集中放在最後一個「其他待確認」區塊。
- 便利貼掛在錨點內，所以**不能用 CSS `filter:grayscale` 整頁轉灰階**（子元素會一起被吃色）：改成圖片先用 Pillow 轉灰階再內嵌，UI 顏色（藍色連結、主按鈕）直接在 CSS 改成灰色。
- 新增後逐張渲染截圖檢查便利貼有沒有互相重疊、超出畫面底部，有就調錨點方向或在該 frame 底部加留白。

### 4.4 空畫面／空白區處理
- 規格定義為「不顯示」的區塊（例：空畫面不顯示卡片），**就讓它空著，不要用淡色圖片「示意位置」補**（使用者明確要求移除）。需要說明就貼便利貼。
- 規格未定義的**是否顯示／行為**，**不自行決定**：虛線框標出＋橘色待確認便利貼。
- **間距、字級、字重、元件樣式細節由 UIUX 設計師掌控**，線框圖用估值即可，**不列待確認、不寫成便利貼**。
- 並排對照（a／b）時各欄寬度不同，示意圖用 `width:100%` 縮放，不寫死像素。

### 4.4a 用詞與便利貼內容（使用者回饋累積）
- **功能區塊預設持續顯示**：除非規格明說不顯示，否則「是否顯示」不要當成待確認（例：空畫面時全選與多筆操作仍持續顯示）。
- **區塊名稱一律用文件原本的名稱**（例：「多筆修改」「多筆操作」），不要自己取「摘要」「摘要文字」這類名稱；不確定文件怎麼叫就先問，不要自創。
- **只改一個地方的捲動／浮動行為**（例：往下捲動後多筆操作變成固定在頁面上方）**不另外畫一張圖**，寫在該區塊的便利貼裡即可。
- **樣式已有既有元件可參照**時，便利貼直接寫「參考○○列表的樣式」，不要列成待確認。
- **使用者已答覆的待確認**：把該項改成黃色規則便利貼（寫答案），沒答覆的才留橘色待確認；整段被答完的「其他待確認」區塊直接移除，答案就近寫成便利貼（例：換頁時「未讀」的狀態要保留 → 貼在分頁上）。
- **只為了展示「勾選後」狀態的情境不畫**（使用者判斷與本次需求無關）；畫之前先想「這張圖在說明本次異動的哪一點」，沒有就不畫。

### 4.5 輸出 PNG 與交接
- 單一情境截圖模式：`index.html#<情境 id>`（例 `#unread`）只顯示該 frame（`body.single`，隱藏側欄與標題），Playwright `device_scale_factor=2`，`locator('.frame.cur .stage').screenshot()`；載圖後 `wait_for_function("document.fonts.status=='loaded'")` 再等 1.5s。
- 檔名用情境 slug（例 `E320_unread_unread.png`、`E320_unread_allread.png`），不用 s1～sN；上傳 R2 時帶 `CacheControl: no-cache`，驗證用 `curl -s -o /dev/null -w '%{http_code}'`（**不要用 `curl -sI | head -1`**：proxy 環境第一行是 `200 Connection Established`，不是真實狀態）。
- 重新產圖後**回報實際尺寸**，與交接文件預期尺寸不同時要明講。
- 交付前把 `index.html` 複製到**空資料夾**單獨渲染驗證，確認沒有外部依賴；改完 commit＋push 指定分支。

## 5. 上線到網站（Cloudflare）

使用者要求把線框圖上線時，讀 [`references/publish-to-site.md`](references/publish-to-site.md)：
- 寫入範圍只限 `wireframe-site/`；推到 `main` 自動部署；網址公開。
- 上線前使用者要明確核可；**去識別化要改到像素層**（截圖轉 base64 內嵌會把原圖帶上去，疊遮罩不算），做法與檢查清單見該檔〈去識別化實作〉。
- 未核可的頁面放暫存目錄，不要放在 repo 裡（stop hook 會要求 commit 未追蹤檔）；推送流程與實測踩坑見該檔〈Cloudflare 推送實測備忘〉。

## 6. 輸出形式：每次開工前先問使用者

使用者之後多半要「能直接貼進 MD 文件看」的 wireframe，但三種形式並存，**每次都先問，不要自己假設**：

| 形式 | 何時用 | 交付 |
| :--- | :--- | :--- |
| **MD 內嵌片段**（預設候選） | 要貼進 HackMD／MD 文件 | 只給 `<div>…</div>` 語法，見 §6.1 |
| 完整 `index.html` | 要自己開檔看、輕量草稿 | 單一檔案，§4.2 自包含規則 |
| 上線 Cloudflare | 要公開網址 | 走 §5，需使用者核可 |

問的時候一句話列出這三項，使用者回答前不要先產出。使用者說「不用 push」就不 commit、不推 `main`；但**用到的圖片仍要上傳 R2**（HTML／MD 只引用 R2 網址）。

### 6.1 MD 內嵌片段規則

- **結構比照 `photo` skill 的 MD 內嵌規範**（另一個 session 已驗證過的 HackMD 安全寫法，**畫面長相仍以本 skill 的風格為準**：灰階、虛線框、覆蓋式改字）。逐條照抄，不要自創：
  1. **最外層白底容器**：`<div style="background:#fff; padding:14px; border-radius:8px;">`——HackMD 深色模式下沒有白底，截圖的深色文字會看不見。**不可省略**。
  2. **圖片用 `<img>`，不用 `background:url()`**；放在 `position:relative; width:100%; max-width:<原圖寬>px; aspect-ratio:<寬>/<高>` 的容器裡，`<img>` 寫 `display:block; width:100%; height:100%; object-fit:fill`。**`aspect-ratio` 必加**，否則百分比定位的疊加元件在 HackMD 會塌陷（photo skill 的真實事故）。
  3. **疊加元件的位置與尺寸一律用 `%`**（`left/top/width/height` ＝ px ÷ 原圖寬或高），不寫死 px，圖縮小時才會一起對齊。
  4. **疊加文字的字級、間距要跟著縮放**：容器加 `container-type:inline-size`，字級寫成 `font-size:15px; font-size:1.426cqw;`（第一個 px 是不支援 cqw 時的備援；cqw ＝ px ÷ 原圖寬 × 100）。
  5. **不用 `<svg>`、`<input>`**（HackMD 可能濾掉）：箭頭 icon 用 CSS 邊框旋轉（`border-right/bottom` ＋ `rotate(45deg)`）；手形 cursor 等圖形先轉成透明 PNG 上傳 R2，再用 `<img>`。
  6. **純圖片也要由外層容器限寬**，不要只靠 `<img>` 自己的 `max-width`（HackMD 的樣式可能蓋掉）。
  7. **不要 `<!doctype>`、`<html>`、`<head>`、`<style>` 區塊**；樣式全 inline。
- **圖片**：灰階後上傳 R2（key 前綴 `photo-skill/`）；改圖換檔名（`_v2`）；上傳後對**片段裡真正寫的網址**逐一 `curl` 驗證 200（不是驗證上傳腳本裡的變數檔名）。
- **新增的元件用虛線框**：`outline:2px dashed #555; outline-offset:3px`，與其他 wireframe 一致；文字用使用者指定的字樣原文，不要自己改寫。
- **擦掉使用者畫在圖上的紅框／標記**：**只把紅色像素換成底色**（`R-G>40 且 R-B>40`，並限制 x 範圍），**不要用整塊矩形塗白**——矩形會連旁邊的邊線一起擦掉（使用者看到的就是「圖片被蓋住、留白」）。擦完裁出來對照原圖確認邊線完整。
- **驗證（比照 photo skill 的敵意模擬）**：
  - 用 Playwright 把片段包進 `<div class="markdown-body">`，並加 `.markdown-body img{max-width:100% !important} .markdown-body div{box-sizing:border-box}`。
  - **viewport 一定要測 760（HackMD 實際欄寬），不要只用寬螢幕**；再測一次寬版對照。
  - 用 `getBoundingClientRect` 程式化檢查沒有元素右緣超出容器，並讀 `aspect-ratio` 容器的實際寬高確認比例正確。
  - 對 Playwright **實際渲染出的截圖**檢查（不是原圖），確認疊加元件位置對、文字沒被截斷；這張截圖就是預覽 PNG，連同片段交給使用者。
- **提醒使用者一個風險**（交付時一句話帶過）：`cqw`（容器單位）需要較新的瀏覽器，不支援時字級會退回固定 px。

### 6.1a 便利貼（說明文字）寫法

- **使用者提供精簡後的說明文字時，原樣放進便利貼**（不增刪、不改寫、不加自己的補充），標題用「區塊名稱」分段；每個區塊一張便利貼，**貼在對應位置旁**，不集中寫在側欄或圖外。
- MD 內嵌版的便利貼也要遵守 §6.1：`position:absolute` ＋ `%` 位置與寬度 ＋ `cqw` 字級，黃底 `#fef08a`、`border:1px solid #eab308`、`box-shadow:2px 3px 0 rgba(0,0,0,.18)`；放在容器內（右緣不得超出容器）。
- **位置避讓**：不蓋住被說明的元件（含虛線框、手形 cursor、導覽列文字）；相鄰便利貼不可互相重疊——渲染後逐張確認，重疊就調 `top`／`left`。壓在未異動的畫面上可以接受。
- 紙條文字的用詞以使用者提供的為準（例：區塊名稱、按鈕舊名），不要自己換成別的說法。

### 6.2 既有頁面截圖改版（導覽列／按鈕／下拉選單）

使用者給整頁網頁截圖，要改 header、側邊按鈕或加下拉選單時：

- **底圖只收「需要的範圍」，不要整頁長圖**：長圖會被上傳流程縮到 640 寬、細節已丟失（實測：同一張圖重傳仍是 640×2000、與原圖逐像素相同）。收到模糊底圖時，直接請使用者只截需要的範圍（例：最上方到左側選單下方，約 1050–1280 寬 × 560–680 高，原尺寸不縮）；**不要硬放大當底圖**，除非使用者同意。
- **用「覆蓋」改文字**（使用者已核可）：新元件用不透明背景蓋住舊文字，不改底圖像素；交付時一句話說明舊文字是被蓋住的。
- **先量座標再畫**：用 numpy 找導覽文字的暗像素欄位分群，得到每個項目的 x 範圍、文字 y 範圍、項目間距、按鈕 bbox 與顏色，再照原間距排版；不要目測。
- **移除導覽項目時**：用白色矩形蓋掉整段舊導覽（只蓋文字區，不蓋 header 邊界），其餘項目依「原間距」往左補位重畫；被改名的項目保留原有的箭頭 icon。
- **hover 展開選單**：項目畫成 hover 底色（淺灰、圓角），箭頭改朝上；選單照使用者提供的選單截圖樣式（白底、圓角約 12、柔陰影、項目高約 44、文字 16px、左內距 24）；同一畫面擺手形 cursor SVG，放在項目文字右下方，**不要蓋住文字或箭頭**。選單與新增項目都用虛線框。
- **新增按鈕**：主按鈕沿用原色轉灰階的色值（取樣原色換算），次要按鈕白底灰框；高度、圓角、寬度與原按鈕一致，垂直間距約 10–12px。
- **預覽圖**：交付 HTML 的同時用 Playwright 渲染一張 PNG 傳給使用者（`SendUserFile`，`display: render`）；改完位置後要重新渲染確認，不能只改座標就交付。

## 7. R2 圖片管理：被 REJECT 的版本，圖片要刪

wireframe 反覆改版會在 R2 留下大量舊圖（模糊底圖、被取代的版本、被移除的情境）。規則：

1. **記帳**：每次上傳到 R2 的 key 都記在對話中（或暫存清單），標明屬於哪個版本。
2. **被 REJECT 的版本所用圖片，要從 R2 刪掉**：使用者明確否決某版（例：「底圖太模糊」「這個情境移除」「留白被蓋住」）、且新版已上傳並被接手後，就刪該版專屬的 R2 物件。
3. **刪之前先確認沒有人在引用**：
   - 用 `grep -rn "<key 檔名>"` 檢查 repo（含 `wireframe-site/`、`handoff/`）與本次交付的 HTML／MD 片段，確認新版沒有沿用同一個 key。
   - 兩版共用的圖不能刪（例：只是改了疊加元件、底圖沒換）。
   - 只刪**本 session 自己上傳**、前綴為 `photo-skill/` 的物件；別人的圖不碰。
4. **不要用同檔名覆蓋來「換圖」**：改圖一律換新檔名（`_v2`、`_v3`），讓舊版可被獨立刪除，也避免 R2／HackMD 快取讓使用者看到舊圖。
5. **刪除方式與驗證**：用 `boto3` 的 `delete_object`（憑證只讀環境變數 `R2_ENDPOINT_URL`／`R2_ACCESS_KEY_ID`／`R2_SECRET_ACCESS_KEY`，bucket 預設 `agent-image-dump`），刪完對該網址 `curl -s -o /dev/null -w '%{http_code}'`，預期 404；回報時列出「已刪除的 key」。
6. **歷史遺留**：skill 上線前已存在的舊圖，不自行清理；列出清單請使用者確認後再刪。
7. **使用者只說「不要 push」**時，圖片規則不變：用到的圖仍要上傳 R2，被否決的版本仍要刪。
