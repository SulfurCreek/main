# 設計描述五層面（把「好看」翻譯成可實作的規格）

> 來源：《給 AI 的設計靈感資源懶人包》（同目錄 PDF，2026.08 整理，6 頁）。
> 本檔把它跟 `html-templates/` 版型庫、§B 自包含鐵律接在一起，變成本 skill 出 HTML 報告時的
> **視覺規格撰寫方法**。

## 為什麼需要這套方法

語言模型處理的是可辨識的名詞與數值，不是主觀感受。「幫我做得好看一點、有質感」沒有可比對的
對象，輸出會落在訓練資料最常見的通用樣式；「editorial 版型、12 欄網格、標題與內文級距差 3 倍、
低彩度淡藍底」每一項都對應具體屬性，可直接落成 CSS、可預期、可逐項調整。
**差別不在指令長度，而在描述的顆粒度。**

寫報告版面時，用同樣標準要求自己：**動手寫 CSS 前，先把五個層面各寫一句、能量化的寫數值。**

## 五個層面（每層一句，通常就足夠）

| 層面 | 要寫什麼 | 本專案報告的範例寫法 |
|---|---|---|
| **字體** | 字型名稱、字重、中英搭配 | 系統字體堆疊（`-apple-system, "Noto Sans TC", sans-serif`）、標題 700、數字用 `tabular-nums` |
| **級距** | 標題／內文尺寸與行高 | 標題與內文級距差 2.5~3 倍（如 34px/13px）、內文行高 1.6 |
| **留白** | 區塊間距、內距、網格欄數 | 區塊間距 48px、卡片內距 20px、KPI 卡 4 欄 grid（窄幅 2 欄） |
| **配色** | 底色數量、彩度、對比策略 | 底色 2 個（surface-1/surface-2）、低彩度、只有數據系列與狀態色帶彩度；沿用 `--series-*`/`--status-*` token |
| **動態** | 觸發時機、位移距離、時間長度 | 靜態報告預設**無進場動畫**；互動只做 hover 顯示 tooltip／高亮列，transition ≤150ms |

> ⚠️ 跟 §B 鐵律對齊：字體層**不可**因參照網站用了某個 webfont 就引 Google Fonts——
> 只能翻譯成「氣質最接近的系統字體堆疊」；動態層在自包含靜態報告裡從簡，位移與透明度為主。

## 使用參照的三個原則（含 html-templates 版型庫的用法）

1. **選 3 個參照，分工不同**：一個定調性、一個定版型、一個定互動。數量多不會提高精確度，
   反而讓描述互相矛盾。從 `html-templates/` 挑時也一樣——例如 `data-report` 定版型骨架、
   `exec-briefing-memo` 定調性、`dashboard` 定 KPI 卡的互動。
2. **標明「借用哪一層」**：借的是版型節奏還是配色邏輯，寫出來。整站／整版複製涉及原創性與
   著作權問題，也難以符合自身內容結構——只借層面，不搬整頁。
3. **一次只調整一個變項**：先固定版型再處理顏色與動態；每輪保留可回溯的版本
   （本 skill 的 pipeline 本來就要求可重跑，正好配合），比較容易判斷是哪一項造成差異。

## 落地流程（接進 §B 標準流程的第 2~3 步之間）

1. 資料聚合完、動模板前，先寫**五層面規格**（五句話，放進報告目錄的 README 或 build script 註解）。
2. 需要參照時：先翻 `html-templates/`，不夠再去上表的資料庫看，**看完轉成五層面的句子**，
   不存截圖不搬原始碼。
3. 產出後驗收（Playwright 雙主題截圖）時，逐層核對規格有沒有走樣——級距、留白是可以量的，
   拿數值對，不要用「感覺差不多」驗收。
