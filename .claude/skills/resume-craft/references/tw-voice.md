# 繁中履歷語氣規範

> 回 [`../SKILL.md`](../SKILL.md)。適用 104、Cake 等所有中文履歷、自傳、專案說明；平台欄位規格各自看 `career/104/`、`career/cake/`，語氣共用本檔。
> 來源：使用者 2026-10-05 親自潤飾稿（`career/style/resume-voice-zh.md` 第 1–3 節）。
> 事實與數字只能來自 `career/wiki/`。語氣可以強，**事實不能誇大**：第 3 節護欄優先於第 1–2 節。

## 1. 使用者偏好的語氣

| 特徵 | 做法 | 例 |
| :--- | :--- | :--- |
| 每條先下標題 | 粗體短標題（4–10 字）＋冒號，再接內容；標題後可加英文術語括號 | **建立單一事實來源（Single Source of Truth）：** … |
| 中英並列關鍵術語 | 專業詞第一次出現時中文＋括號英文，方便 HR 與 ATS 同時命中 | 世代分析（Cohort Analysis）、定價策略（Pricing Strategy） |
| 主動、結果導向的動詞 | 主導、統籌、制定、收斂、締造、實證、帶動、引導 | 「統籌 227 項 Roadmap」而非「負責 Roadmap」 |
| 先講商業意義再講做法 | 每段收在「對公司帶來什麼」：留存、變現、交付速度 | 「產品的終極目標是變現與留存。」 |
| 自傳分主題段 | 每段一個【小標】，三到四段：定位 → 技術與架構 → 商業與 AI → 前 90 天 | 【技術力與架構思維｜…】 |
| 句子連貫、有轉折 | 用「面對…，我…」「此外」「透過…，我讓…」串成敘事，不是條列碎句 | 「面對龐大的系統包袱，我主導了…」 |
| 自信但具體 | 形容詞後面一定接數字或具體做法 | 「卓越紀錄」後面接「半年 111 項、94% 準時」 |

## 2. 結構範本

1. **【核心能力與專業定位】**：3 條，每條「粗體標題（英文）：一句能力＋一個代表數字」。
2. **【工作經歷】**：每家公司 3–5 條，每條「粗體標題：情境 → 我做了什麼 → 結果數字」。
3. **【中文自傳】**：3–4 個【小標｜副標】段落，每段 ≤ 5 行（自傳段落長度以 `assets/template-tw-zh.md` 的手機可讀規則為準，兩者衝突時取較短者）。
4. **【英文自傳】**：3 段，第一段定位、第二段現職、第三段前職＋AI＋語言證照。

## 3. 護欄（比語氣優先）

| 不可以 | 原因 | 改法 |
| :--- | :--- | :--- |
| 寫證據沒有的形容（如「零停機」「Zero-Downtime」） | 面試追問答不出來 | 只寫有證據的：「向下相容的漸進遷移」 |
| 改變數字的意思（如把「註冊數 +67%」寫成「註冊轉換率 +67%」） | 指標不同，被追問就破功 | 照 wiki 原指標名 |
| 把範圍放大（如把「企業名冊」寫成「客戶」、「維運工單」寫成「客服工單」） | 同上 | 照 wiki 原描述 |
| 給產品貼上沒確認的標籤（如「訂閱制」） | 只有 wiki 已確認的才能寫 | 查 wiki，沒確認就寫中性說法（如「社交 App」） |
| AI 腔字眼：intricate、exponential(ly)、realm、pivotal、showcasing、極度、無與倫比 | 易被判定 AI 生成（見 `ats-and-ai-screening.md`） | 換成具體動詞或刪掉 |
| 營收、分潤絕對金額 | 使用者保密決定 | 只寫比例與倍數 |
| 自傳、專案說明含姓名、電話、地址 | 104 明文禁止 | 刪 |
| 文中出現 `[cite: …]` 等引用標記 | 生成工具殘留 | 輸出前全文檢查刪除 |

交付前再跑一次：全文 grep `cite`、`〔待`、`TODO` 零結果；每個數字都能在 `career/wiki/` 找到原句；第 3 節禁用字眼零出現。
