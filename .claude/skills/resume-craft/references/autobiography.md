# 自傳寫作：四段敘事（essay → 潤飾）

> 回 [`../SKILL.md`](../SKILL.md)。**2026-10-12 重構**：使用者認為先前的分主題自傳「非常不自然」，提供〈Executive Storyteller〉四段敘事法（原文 `career/style/autobio-storyteller-source.md`）。本檔取代舊的「3–4 個主題段＋小標」寫法。
> 也整合：離職動機（`career/style/leaving-reason-source.md`）、去 AI（`career/style/de-ai-reverse-engineering-source.md`）、使用者價值觀與做事流程（`career/library/profile.md` §8，**推論、待使用者確認**）。
> 版面：`assets/template-tw-zh.md`〈自傳〉；語氣：`career/style/resume-voice-zh.md` §9。

## 為什麼改

舊寫法每段一個主題（判斷、商業化、協作、事故、動機），讀起來像「針對主題的 Q&A」；HR 看到的是一張特質清單，不是一個人。自傳要是**一個有脈絡的故事**：特質藏在解決一個具體痛點的細節裡，不直接寫「我很會溝通」。

## 結構：四段，不加段

| 段 | 名稱 | 長度 | 寫什麼 | 不寫什麼 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 破題（Hook） | 1–2 句 | 用一句話說出**使用者自己做產品最在意的事**（價值觀），取自 `profile.md` §8 | 「您好，我是…畢業於…」；宇宙通則（「最難的從來不是…」） |
| 2 | 關鍵戰役（Battle） | 最長，約全文一半 | **只挑一個**專案：當時的混亂或限制（S）→ 我做了什麼、哪裡跟直覺做法不同（A）→ 結果（R，最多 1–2 個數字） | 經歷總覽；每個專案都提一下；直接寫「溝通、抗壓」 |
| 3 | 方法（Methodology） | 2–3 句 | 從這場戰役帶走的做法，**寫成我現在怎麼做事**，可以延伸到第二個例子一句帶過 | 口號；「好的 PM 應該…」這種對別人的規定 |
| 4 | 動機與對齊（Ask） | 2–3 句 | 貢獻 → 想投入的方向（拉力）；有目標 JD 時接上「貴公司的〔某挑戰〕」 | 「現有架構難再突破」（書面讀成負面）；客套謙詞；90 天清單（放求職信） |

- 總長 500–800 字；**不加段落小標**（四段本身就是結構；舊的「每段一個小標」作廢）。
- 段與段之間要有因果連接：Hook 的信念 → 在戰役裡被考驗 → 沉澱成方法 → 所以想去哪裡。

## A. 先寫 essay（3b，`03b-autobio-essay.md`）

1. **選戰役**：從步驟 3 的 essay 挑一篇，條件是（a）有混亂或限制（b）有使用者自己的、非直覺的決定（c）有結果（d）事實在 library 裡完整。選定後寫一行理由。
2. **寫 Hook 候選 3 句**：都從 `profile.md` §8 的價值觀出發，寫成「我」的信念，不寫通則。
3. **戰役 essay 不限字數**：場景（誰、卡在哪、時間壓力）→ 我的判斷與取捨 → 我實際做了什麼（產出文件、對齊了誰）→ 結果 → 我負責與不負責的範圍。HR 在意的特質（溝通、抗壓、當責）**用細節呈現**，在 essay 旁邊標註「這句呈現哪個特質」，正文不寫特質名稱。
4. **方法 essay**：這個做法還用在哪一件事（一句即可，例：配對規則、承攬制、搜尋邏輯）。
5. **動機 essay**：依下方〈離職動機〉。

每篇開頭標：

```text
想讓讀者相信：（一句話）
素材來源：（library 條目或步驟 3 essay 編號）
```

## B. 潤飾成四段（3c，`03c-autobio-draft.md`）

- 依上表四段落濃縮；語氣像資深職人在咖啡廳跟另一位主管講一個難搞的案子：自信、落地、從容，不炫技。
- 句子長短交錯；不寫對仗、不寫三連排比（「我學會了溝通，提升了效率，創造了價值」）。多動詞，少形容詞與副詞。
- 數字最多 1–2 個，只放在戰役段的結果；其餘數字留在履歷條列，不重述。
- 潤飾後**一定接步驟 4（每段 20 版本）與步驟 5 去 AI 感**，再跟履歷一起過 HR、ATS、主管檢測。

## 去 AI 禁用（本檔專用，另見 `anti-ai-ats.md` §1）

深入探討、至關重要、不可或缺、值得注意的是、總而言之、展現了、不僅…更是、充滿熱情、積極進取、期許自己、挑戰自我、團隊合作能力、抗壓性極佳；另禁「熱愛學習、希望來學習、即戰力、高適應力」。

## 離職動機（第 4 段的寫法）

### HR 為什麼問

1. 探詢動機。
2. 找出你的「地雷區」評估留任：你無法接受的事（文化、主管風格、工作性質），新公司會不會也有。
3. 用過去預測未來：一直把問題歸給外部環境的人，進來後也會有同樣摩擦。

### 不能寫的三種理由（即使是真的）

| NG | HR 的聯想 |
| :--- | :--- |
| 跟主管管理風格不合 | 會不會是你的個性或配合度有問題 |
| 跟同事相處不好 | 溝通或團隊協作有問題 |
| 工時太長、常加班 | 配合度低；遇到配合度高的候選人就被比下去 |

另外不寫：批評前公司或組織（「停擺」「前任主管沒做完」「能做的我已經做到」）、薪資。

### 寫法：把推力轉成拉力

順序固定三步（原文公式）：

1. **先寫貢獻**：在現職主導了什麼、學到什麼（具體、有數字，跟前面段落不重複）。
2. **再寫「已到一個階段」**：用中性說法，例如「工作已趨於平穩」「組織發展到了一個階段」「在現有架構下較難有突破」。不指向任何人。
3. **最後寫想投入的方向（拉力）**：想累積什麼樣的經驗、想挑戰什麼；有目標 JD 時，接上「貴公司的〔某項業務或挑戰〕正是我想投入的方向」。

原則：誠實但避重就輕（不編理由）、不批評、聚焦有計畫的職涯發展。

**書面自傳只寫第 1、3 步（貢獻 → 拉力），第 2 步「已到一個階段」留給面試口頭說明**（2026-10-12 盲審 v8：「在現有架構下比較難再有大的突破」5／5 輪被判組織負面敘事；書面讀者沒有語氣與表情可以緩衝）。

### 使用者的對照（`library/profile.md` §7）

| 內部真話（不直接寫） | 對外寫法方向 |
| :--- | :--- |
| 多半在舊系統、業務與技術單位之間協調與執行 | 貢獻：舊系統改版、需求窗口、交付成果 → 「這幾年把交付與跨部門流程做穩了」 |
| 產品方針不變的前提下，能做的已經做到 | 階段（**只在面試口頭說**）：「這套系統的改版與流程已經上軌道」；書面省略 |
| 想參與產品方向的決定 | 拉力：「下一步想在更早的階段參與產品方向，從問題定義到成效負責」（**不要寫成現職沒有決定權**） |

已被盲審點名的風險句：「能做的我已經做到」（負面）、「想參與決定要做什麼」（被讀成現職沒有決定權）。
## 與既有規則的衝突與處理

| 衝突 | 處理 |
| :-- | :-- |
| 四段固定 vs 舊規則「3 個案例＋事故＋動機」（ChatGPT 審查採用項） | 四段為準；其他案例留在履歷條列與面試；事故不進自傳 |
| 戰役要量化結果 vs「自傳不重述履歷數字」 | 戰役段可用 1–2 個數字，且要換角度（寫當時為什麼這樣決定）；其餘不重述 |
| Hook「核心信仰」範例是通則句 vs v8 盲審「概括性絕對語氣」扣分 | Hook 寫成使用者自己的信念（「我做產品最在意的是…」），不寫「從來」「最難的永遠是」 |
| 原文要求先問「目標職位、核心專案、1–2 個特質」 | **不問使用者**（2026-10-12 使用者：這些 library 都有了）：目標職位取自 `104/jd-digest-A.md` 或使用者指定 JD；核心專案依〈A. 選戰役〉從 library 挑；特質取自 `profile.md` §8 |
| 舊規則「每段一個小標」（`tw-voice.md`、`resume-voice-zh.md`） | 作廢，以本檔為準 |
| 「違反直覺／捲起袖子」的行動 | 只能用 library 有的事實；沒有就寫實際做的事，不為了戲劇性加情節 |

## 檢查清單（3c 出口）

- [ ] 剛好四段；沒有段落小標；沒有主題清單式段落。
- [ ] 戰役只有一個；有場景、非直覺的決定、結果；特質沒有被直接點名。
- [ ] Hook 是「我」的信念，不是通則；跟方法段前後呼應。
- [ ] 數字 ≤ 2 個且不重述履歷條列；每句對得回 essay 與 library。
- [ ] 第 4 段：貢獻 → 拉力；無 NG 三理由、無批評、無「難再突破」、無客套。
- [ ] 禁用詞 0、對仗與三連排比 0（`scripts/resume_score.py` 旗標 0）。
