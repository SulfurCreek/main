# 跨文件引用 ・ 待補規則區塊 ・ 階段拆分

> 回 [`../SKILL.md`](../SKILL.md)。

## 跨文件引用與嵌入（三層方式）

引用既有文件時依「讀者需要看多深」選擇：

### 1️⃣ 行內連結 — 讀者只需要知道去哪看

相對 note 路徑連結，用在權限表、入口頁、其他功能文件：

```markdown
| 權限條件 | 代碼 [求才系統代碼表](/B1j3sN-bzx) | 不符合時的處理 |
* [信件列表](/uoldEfXhT9KrbGxQJwg4ew) 訊息列表點擊任一對話
* 點擊外開分頁前往[封鎖名單](/I3yns2xqQiuwVIEfEHAxhw)
```

### 2️⃣ iframe 開啟現版功能 — 沿用現版 lightbox 時

說明點擊行為 + **iframe 尺寸** + **帶入參數**，並連結該 lightbox 的規格文件：

```markdown
* **訊息來往紀錄**：
  * 點擊後，以iframe方式開啟現版 [紀錄管理Lightbox](https://hackmd.io/@1111-jobdocs/Sk4AvcZ-We)
    * iframe尺寸：800x680
    * 帶`求職者姓名`、`tNO`、`oNo`
    * landing在`信件紀錄管理`
```

### 3️⃣ 全文嵌入 — 讓讀者不離開本文即可展開閱讀

`{%hackmd <noteId> %}` 嵌入語法，包在 `:::spoiler` 內、外層 `<div style="padding-left:50px">` 縮排。
**緊跟在 2️⃣ 的 iframe 說明之後**，作為該 lightbox 規格的就地參照：

```markdown
<div style="padding-left:50px">

:::spoiler 紀錄管理Lightbox

{%hackmd Sk4AvcZ-We %}

:::

</div>
```

> 引用舊版規格的特定章節時，連結文字註明版本與章節：`（舊版 [4.1 v1.0.1／§4.3](/r1ghrPxP-x)）`。

## 待補規則區塊（🚧 warning）

規格有缺口、需要 PM／設計確認時，不要只寫一行 `待補`——用 `:::warning` 區塊完整記錄缺口脈絡，固定四段結構：

```markdown
:::warning

* **🚧 待補規則 {編號}：{主題}**

<font style="color:red">

* 現況：{目前文件／Figma 寫了什麼}
* 缺口：
  * {具體未定義的問題 1}
  * {具體未定義的問題 2}
* 待確認：
  * [ ] {要 PM 回答的具體問題}
  * [x] {已確認的項目（保留紀錄）}
* 來源：{Figma／示意圖／舊版文件 出處}

</font>
:::
```

- 已有合理推測時，在「待確認」用 `[x]` 標出推測內容並註明「待確認沿用」。
- 衝突類缺口（新舊版規則不一致）寫明**兩邊數值與出處**，標明「以何者為準待 PM 確認」。

## 階段拆分（第一階段／第二階段）

功能分階段交付時，**第二階段內容拆成獨立文件**，不混在第一階段文件內：

- 第二階段文件開頭註明：`> 以下項目第一階段先保留畫面入口、功能延後至第二階段實作。`
- 從第一階段移出的每一節，記錄出處：`> 來源：原 §1.2 訊息列表 搜尋與工具列（1.2.2）。`
- 第一階段文件保留畫面入口的描述，並連結至第二階段：
  `* [更多範本](#更多範本按鈕)為第二階段功能`、`詳見 [第二階段內容](#第二階段內容)`
- 第二階段文件沿用同一份文件骨架（User Story／Document info／版控）。
- 跨系統後端邏輯（共同發送／回覆行為、類型對照、完整 mermaid 流程圖）放在階段文件的獨立章節，
  **不重複貼在兩份文件**。
