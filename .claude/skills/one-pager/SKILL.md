# One-Pager 產生器（單張 PNG 決策/摘要海報）

把資訊濃縮成**一張橫式圖**：讀者 5 分鐘看完、當場能做一個決策或行動。核心是「精煉」——
砍到只剩最關鍵的、排成一眼可掃的結構，最後輸出 **PNG 圖檔**。

> 與 `report-generator` 分工：report-generator 產「多段、可捲動、可搜尋」的 MD/HTML 報告；
> one-pager 產「單畫布、固定尺寸、給人看一眼、輸出 PNG」的海報。兩者共用「結論先行、精煉、
> 語意配色」的 DNA。圖表配色規範仍以官方 `dataviz` skill 為準。

## 🚦 兩道硬規則（絕對不可跳過）

1. **GATE①：出圖前先給純文字大綱等使用者確認。** 把整張圖的所有文字（kicker、大標、每欄名、
   每一列/每一格、解說卡、頁尾）用 markdown 列出來貼給使用者，**明確問「這樣的文字內容可以嗎？」**
   使用者核可（或改完再核可）後，才進到填模板、出圖。不要一次做到底。
2. **GATE②：最終交付是 PNG，不是 HTML。** HTML 只是中間鷹架，用完可丟；交付一定是 `.png`，
   用 `SendUserFile`（`display: render`）送出。

## ⭐ 核心鐵則：資訊自足——「不能只有結論/數字」（本 skill 的靈魂）

一張 one-pager 要**被單獨轉發（截圖丟群組、沒任何附帶文字）也能被零背景的人完全看懂**。
所以：**每一個項目、每一個數字，都要能自我說明**，至少回答三件事（缺一不可）：

1. **是什麼**：白話定義。數字一定要講**分母**（✅「命中率＝廠商送出的職類，出現在 AI 前5名推薦的比例」）。
2. **從哪來**：來源／怎麼算／**比較基準／樣本數／時間**（直接回答「數字從哪來？」）。
3. **代表什麼**：so-what——好還是壞、比誰、達標沒（✅「79.7%，比舊版 61.8% 高 +17.9pp」）。

> ⛔ **裸數字 dashboard 明令禁止**：大數字旁邊沒有白話定義、沒有對照基準、沒有來源，就是不合格，不准出圖。
> 「只有 dashboard 很難傳遞資訊」——一張只有結論/數字、沒有說明的圖，對沒有 context 的人等於沒有資訊。

## 版型 DNA（由上而下的帶狀區塊）

所有 one-pager 共用同一套骨架，只有中間 **body** 換版型：

1. **kicker 情境列**：小字＋accent 直條。含情境定位＋「閱讀時間」（例：`… · 5 分鐘`）。
2. **大標**：巨大粗體，內含一段換色強調（`<em>…</em>`）。**標題講「要做的決策/結論」，不是主題**
   （✅`請勾：該不該上` ❌`負回饋選項說明`）。
3. **背景句（`context`，內部題材必備）**：一句白話讓零背景的人知道**這是什麼／給誰／要幹嘛**，
   並在這裡就把主要名詞定義掉（例：「命中＝廠商送出的職類有出現在 AI 前5名裡」）。
4. **body（主角）**：四選一版型，見下。
5. **符號鍵（`keys`）**：把圖上用到的**每個顏色/符號/emoji 的意義逐項寫明**（綠=什麼、紅=什麼、
   琥珀=什麼）。不要讓讀者用猜的。
6. **解說卡列（`cards`，0~3 張）**：回答讀者「但為什麼／X 是什麼」的預期問題。**抽成卡片，不塞進主表**。
7. **來源帶（`source`，涉及數字必備）**：一條窄帶固定放 **資料來源 · 比較基準 · 樣本數 · 時間**。
   這是「數字從哪來」的統一答案。
8. **頁尾**：主要行動（按鈕樣）＋進度／圖例／頁碼。把「讀完要做什麼」講明。

視覺語言：深色、單一 accent（藍）、語意狀態色（綠=正向/通過、紅=排除/警示、琥珀=關鍵數值/期限）、
高密度但**每格短（中文 ≤ ~15 字）**、格內只粗體關鍵字、emoji 當列識別。

## 精煉方法（把資訊砍到只剩一張圖）

- **一列一決策單位**：每列自足，讀者能只看一列就行動。
- **欄位平行**：每一欄跨所有列回答**同一個問題**（例：這欄都在講「系統做什麼」）。
- **標題是結論不是主題**；頁尾把行動講明。
- **預期問題外掛成解說卡**，不污染主表。
- 砍字原則：能用詞就不用句、能用數字就不用形容詞、重複的字提到欄名去。
- **裝不下時：縮小範圍守住一頁，不砍說明。** 說明（定義/來源/so-what）是本 skill 的重點，不能為了塞更多
  項目而刪掉說明。一頁只講一件事——項目太多就把題目切小（例：只講「命中率改善」不要同時講退步分析），
  或減少 KPI 磁磚數（≤4 個）留出說明空間。

## 四種 body 版型與內容 JSON

內容用一份 JSON 描述，`layout` 決定 body 版型。四種：

| layout | 何時用 | body |
|---|---|---|
| `decision_matrix`（主，對齊範例） | 多選項各要一個 yes/no 決策 | 表頭＋N列，末欄勾選 chip |
| `comparison` | 2~4 方案並排比優劣 | 欄=方案、列=維度，格內語意色 |
| `kpi` | 一組成效數字一眼看完 | 大數字卡片列 |
| `checklist` | 上線前/交付前逐項確認 | 分組核取項＋狀態燈 |

共用欄位（**粗體＝資訊自足必備**）：`kicker`、`headline`（可含 `<em>`）、**`context`**（背景句，內部題材必備）、
**`keys`**（符號鍵 `[{color?, sym?, text}]`）、`cards`（`[{title, body}]`，0~3 張）、
**`source`**（`{source, baseline, sample, time, note}`，涉及數字必備）、`footer`（`{action, progress, legend, page}`）。
各版型專屬欄位：

```jsonc
// decision_matrix — 每列跨欄自我說明（選項→系統做什麼→有效期→AI學什麼）
"matrix": { "columns": ["…5欄名…"], "rows": [
  { "emoji":"💼", "option":"…", "action":"…（可含 <b>）", "ttl":"90/30 天",
    "learn":"…", "learn_status":"good|bad", "verdict":"check" } ] }
// comparison — 維度可加 note 一句說明
"comparison": { "options":["方案A","方案B"], "rows":[
  { "dim":"成本", "note":"一次性導入費", "cells":[ {"text":"低","status":"good"}, {"text":"高","status":"bad"} ] } ] }
// kpi — 每個數字強制 define(是什麼/含分母) + compare(對照/好壞)，不可只有 value+label
"kpi": { "tiles":[ {
  "label":"命中率（前5名內）", "value":"79.7%", "tone":"good|bad|accent",
  "compare":"舊版 61.8% <span class=\"up\">▲ +17.9pp</span>",   // ▲ up=綠 / ▼ down=紅
  "define":"每 100 筆職缺，有 79.7 筆的廠商送出職類出現在 AI 前5名。越高越準。"
} ] }   // 磁磚 ≤ 4 個，留說明空間
// checklist — 項目可加 note 一句說明
"checklist": { "groups":[ {"title":"資料","items":[ {"text":"去重完成","note":"移除 1.5 萬重複","state":"done|todo|warn"} ]} ] }
```

完整可跑範例：
- [`assets/example_decision_matrix.json`](assets/example_decision_matrix.json)（重現使用者提供的 7 選項海報，含 context/keys/source）。
- [`assets/example_kpi.json`](assets/example_kpi.json)（**自我說明版 KPI**：每個數字都有定義＋對照＋來源帶，示範如何避免裸 dashboard）。

## 標準流程

1. **釐清目標**：這張圖要驅動什麼決策/傳達什麼摘要、誰讀、讀完的唯一行動是什麼；選 `layout`。
2. **精煉成純文字大綱**：把 kicker、大標、每欄名、每列每格、解說卡、頁尾全部寫成 markdown。
3. **🚦 GATE①：貼大綱給使用者，問「這樣可以嗎？」等核可**（改完再核可）。
4. 把核可內容寫成 `content.json`。
5. 產圖（在 skill 的 `assets/` 目錄跑，或把 assets 複製到工作區）：
   ```bash
   python3 assets/build.py content.json out.html
   NODE_PATH=/opt/node22/lib/node_modules node assets/render_png.js out.html out.png
   ```
6. **看 PNG**（用 Read 開圖）並做**冷讀者測試**：
   - 中文有無缺字（豆腐字）、欄位有無溢出/重疊、密度是否過擠。
   - **遮住標題，隨機指一個數字/項目——一個完全沒有背景的人，能不能只看圖就說出它「是什麼、從哪來、
     代表好還是壞」？** 答不出來就是沒過：補 `define`/`context`/`source`/`keys`，重跑步驟 5。
7. **🚦 GATE②：`SendUserFile`（`display: render`）交付 `.png`**。HTML 為暫存鷹架，不是交付物。

## 已定案的技術參數（不要隨意改）

- **畫布**：16:9 橫式 **2000×1125**；`render_png.js` 用 `deviceScaleFactor:2` → **4000×2250** 高解析 PNG。
- **字型**：系統 **文泉驛正黑（WenQuanYi Zen Hei）**——本環境唯一可靠的中文字型。粗體是瀏覽器合成，
  所以**靠字級大小拉出層次，不要依賴細字重**。不要嵌外部字型、不要連 CDN（維持自包含）。
- **render 路徑**：Chromium `/opt/pw-browsers/chromium`（勿 `playwright install`）；
  Playwright 在 `/opt/node22/lib/node_modules`（故 `NODE_PATH=/opt/node22/lib/node_modules`）。
- `render_png.js` 會攔截 pageerror／console error，有 JS 錯誤會 exit 非 0——**別忽略**。

## 反例對照

| ❌ 不要 | ✅ 要 |
|---|---|
| 直接做圖給使用者看 | 先列純文字大綱等核可（GATE①） |
| 交付 HTML 或截圖連結 | 交付 PNG 檔（GATE②） |
| **裸數字：只有「79.7%」+ 標籤** | **數字＋白話定義（含分母）＋對照基準＋來源帶** |
| **只有結論/dashboard，沒說明** | **每個項目自我說明：是什麼／從哪來／代表什麼** |
| **數字不交代來源** | **來源帶固定放：資料來源·比較基準·樣本·時間** |
| **顏色/符號要讀者用猜的** | **符號鍵逐項寫明綠=什麼、紅=什麼** |
| 內部題材沒有背景句 | 一句 `context` 讓零背景的人懂「這是什麼/給誰/要幹嘛」 |
| 專有名詞（TTL、命中率）不解釋 | 第一次出現就展開或附迷你詞義 |
| 標題寫主題（「選項說明」） | 標題寫決策（「請勾：該不該上」） |
| 一格塞一整句話 | 一格 ≤ ~15 字，只粗體關鍵字 |
| 為了塞更多項目而砍掉說明 | 縮小範圍守住一頁；說明不能砍，題目切小 |
| 依賴細字重做層次 | 用字級大小＋語意色做層次（字型無細字重） |
