# 履歷審查模擬小組

> 狀態：2026-10-06 由 career session 建立草稿，使用者同日核可、主幹收錄到 `.claude/skills/`。
> **使用限制（先讀）**：
> 1. **素材只在個人線分支 `claude/happy-lamport-ljis8c`**（`career/review-panel/`、`career/wiki/`）。從 main 開的 session 看不到，要用請在該分支工作，或先 `git fetch` 後用 `git show` 唯讀讀取。
> 2. **只產審查報告，不改履歷**；寫入位置只限 `career/`（不是 career session 的 session 要寫報告，請先確認所在分支與目錄所有權，見 `wiki/personal_line_collab.md`）。
> 3. **審查結果是結構化的自我檢查，不是真人意見**（見文末〈可靠度〉）。

## 素材
| 檔案 | 用途 |
| :--- | :--- |
| `career/review-panel/research.md` | 審查角度的研究依據與來源；**每條審查意見都要能對回這裡或 wiki** |
| `career/review-panel/research-hr-hm-2026-10-08.md` | 人資／用人主管關注點 100 條（v2 清單的來源，編號 1–100） |
| `career/review-panel/reviewers/hr.md` | H1–H10 人資 persona 與共通清單 |
| `career/review-panel/reviewers/hiring-managers.md` | M1–M10 用人主管 persona 與共通清單 |
| `career/review-panel/candidates/` | 50 份虛構同儕履歷（含 A／B／C 品質分級），當比較基準 |
| `scan.py`（本 skill 目錄內） | 機械掃描（數字比例、基準值、職責式條列、空泛詞、術語密度、軟實力關鍵字） |
| `career/wiki/`、`career/wiki/soft-skills.md` | **事實的唯一來源**，用來抓誇大與遺漏 |

## 流程（依序，不可跳步）

### 1. 事實核對（先做，避免審到假內容）
逐條把履歷的數字與主張對回 `career/wiki/`：標出 ✅ 有證據／⚠️ 措辭超過證據／❌ 找不到證據。
也列出 **wiki 有、履歷沒寫** 的重要事項（尤其使用者指定的代表作與軟實力）。

### 2. 機械掃描
```bash
python3 .claude/skills/resume-review-panel/scan.py <履歷.md>
python3 .claude/skills/resume-review-panel/scan.py --pool career/review-panel/candidates   # 同儕分布
```
**選用**。只用來抓「C 級問題」：職責式條列、空泛詞、沒有數字。**報告裡不要引用它的總分**，也不要用總分判斷好壞（可靠度見下）；只引用個別指標（職責式條列比例、數字比例、空泛詞次數）。
另外人工記下術語的**絕對次數**（密度會被長文稀釋）。

### 3. 20 位審查者逐一審查
對每位 persona，依其表格欄位輸出一行：
`編號｜7–10 秒印象｜分數 1–5｜會不會往下送｜最大扣分點（引用履歷原句）｜最想問的問題`
規則：
- 只能根據 persona 的「先看哪裡、必要條件、紅旗」判斷，不要每位都講一樣的話。
- 扣分點必須**引用履歷原句**；不能引用就不能扣分。
- **v2 共通清單**：除了 persona 本身的 7 項（人資）或 6 項（主管），每位審查者另依 `career/review-panel/reviewers/*.md` 的〈共通審查清單 v2〉逐項檢查（人資 HR-A…HR-G、主管 HM-A…HM-G，含詳略校準），扣分時寫出對應編號。
- 人資與用人主管分開彙總。

### 4. 同儕比較
從 50 份中挑與目標職缺最接近的 5 份（產業與年資相近，至少 1 份 A 級），
比較：第一屏資訊量、成果寫法、軟實力證據、術語密度、語氣是否像本人。
只說「哪裡比對方好／差」，不要抄同儕內容。

### 5. 彙整報告（寫到 `career/104/review-<日期>.md` 或對應平台目錄）
1. 總結（3 行內）：會不會過人資初篩、會不會打動用人主管。
2. 問題清單：依「被幾位審查者提到 × 嚴重度」排序，每項附原句與建議方向（不改寫全文）。
3. 事實核對結果（第 1 步）。
4. 審查者分數表（20 行）。
5. 已知盲點：本次審查無法判斷的事（例如真實薪資帶、特定公司文化）。

## 禁止
- 不改使用者履歷；不替使用者編造數字或經歷。
- 不把虛構 persona 說成真實人士或真實公司意見。
- 不用同儕履歷的內容填補使用者履歷。

## 可靠度（2026-10-06 自評，詳見建立時的回報）
- 機械掃描在 50 份同儕池：A>C 排序正確 93%、B>C 89%、**A>B 只有 61%**；且分級與關鍵字都由同一個人（Claude）設計，有循環論證風險。
- 機械掃描給使用者 10/06 履歷 82.8 分（偏高），**抓不到**使用者自己指出的「技術詞過多、軟實力不足」——因為「客服、法務、帶」等詞被算成軟實力。→ 軟實力與語氣判斷必須靠第 3 步人工審查，不能靠分數。
- 20 位 persona 由同一個模型扮演，意見會比真人更一致；**不能取代真人回饋**，最好再找 1–2 位真實人資或主管看過。
