Technical Specs & Flow Logic

資料來源（全畫面共用）
事件 recruit:login:success，clientId/system = recruit-web，只收正式環境。前端在 ReturnState:1 送出；ReturnState:7（裝置驗證）、6（重複登入）最後都回到 1，一次登入只記一筆，所以「登入次數」= 事件筆數，不需再去重。
可用欄位：時間戳記、IP（判斷內外網）、抵達頁面、oStatus、OrganNo（metadata）、廠商名稱、tCodeTrade、廠商帳號、oUser（= UserID）、裝置。畫面不使用其他欄位。
⚠ 本草稿依交接文件的欄位清單繪製；HackMD 原文（3iGPEf82SO2bAwrQ55hngg）因環境網路政策擋下 api.hackmd.io 未能直接讀取，需對原文覆核一次。
① 篩選列
日期：單日（只填起始日）／區間（起迄皆填，含首尾兩日）。依時間戳記 yyyy/mm/dd 部分比對。
oStatus：多選 0–6（0 普通會員／1 VIP／2 過期／3 關權／4 免費VIP／5 免費曝光／6 準VIP）。
產業：tCodeTrade；裝置：desktop／mobile；內外網：由 IP 判斷。
所有篩選條件同時套用到 ②–⑥。
🚧 待確認：內外網判斷的欄位名稱（需求只寫「需有欄位可判斷」），以及前端送出時如何取得真實 IP。
② 當日總覽
登入廠商數 = COUNT(DISTINCT OrganNo)
登入帳號數 = COUNT(DISTINCT UserID)
登入次數 = COUNT(*)
內網／外網比例、desktop／mobile 比例 = 各類事件筆數 ÷ 登入次數。
區間模式：去重範圍是整個區間（同一廠商連續 7 天登入只算 1 家），不是每日數字加總。
🚧 待確認：內網「客服人員直接登入」是否也會送出事件；若會，要不要從所有統計中排除（目前畫面未排除）。
③ 每日趨勢
近 N 天（7／14／30 可切換），X 軸 = 日期，兩條線：每日 DISTINCT OrganNo、每日 DISTINCT UserID。每天各自去重。
N 天的終點 = 篩選列的結束日（單日模式即該日）。
④ 廠商列表
以 OrganNo 分組，每列一家廠商：
廠商名稱、OrganNo、oStatus、產業 = 該廠商在期間內最後一筆事件的值；
登入帳號數 = 該廠商的 DISTINCT UserID；登入次數 = 事件筆數；最後登入時間 = MAX(時間戳記)。
預設依登入次數排序，可點欄位改排序；搜尋框比對廠商名稱或 OrganNo。點列 → 展開 ⑤。
區間模式下欄位名稱的「當日」改為「期間內」。
🚧 待確認：同一天內 oStatus 或廠商名稱若有變動（例如 VIP 到期），列表取最後一筆值是否符合需求。
⑤ 帳號明細（展開列）
每列 = 一筆登入成功事件，不去重：帳號（廠商帳號）、UserID（oUser）、登入時間、內外網、裝置、抵達頁面。
抵達頁面 = 登入後的 URL 路徑；沒有指定時記為首頁，畫面顯示「/（首頁）」。
🚧 待確認：明細是否需要顯示原始 IP（目前只顯示判斷後的內外網）。
⑥ 分布
依 oStatus：各代碼的 DISTINCT OrganNo，7 個代碼全列（含 0 筆）。過期／關權用灰色以示區隔。
依產業：各 tCodeTrade 的 DISTINCT OrganNo，顯示 Top 8，其餘併入「其他」。
🚧 待確認：tCodeTrade 是單值還是多值。若多值，一家廠商會被算進多個產業，各產業加總會大於登入廠商數，需在圖上註明。
