# 盲審 v3.1：6 秒初篩提示＋盲審輸出格式

> 2026-10-09 依 `../style/hr-6-second-source.md` 建立。用法見 `resume-review-panel` SKILL.md〈驗證機制 v3〉項目 1、3。
> 兩段都交給**寫稿者以外的模型**，在新 context 裡執行，不給 library、essay、改稿理由。

## A. 6 秒初篩（每份履歷一次，含 C 級同儕當校準）

先產 F 型視野：

```bash
python3 .claude/skills/resume-review-panel/scripts/f_scan.py <resume.txt> --view-only > fview-<代號>.txt
```

提示（整段貼給審查模型，`{職缺摘要}` 用 `104/jd-digest-A.md` 的一筆，`{F型視野}` 貼上檔案內容）：

```text
你是台灣軟體業的招募專員，每天看上百份履歷。下面是一份履歷「你在 6 秒內眼睛實際掃到的字」：
上方幾行看得到全句，之後每行只看得到開頭幾個字（…表示後面你沒看到）。
只能根據看得到的字回答，看不到的不要猜；猜不出就寫「看不出」。

目標職缺：{職缺摘要}

{F型視野}

只輸出 JSON：
{"title": "最近一份工作的職稱", "company": "目前或最近的公司", "years": "總年資（數字或看不出）",
 "can_do": "是／否／不確定", "can_do_evidence": "依據哪一句（引用看得到的字）",
 "yes_reasons": ["最多 3 個讓你想說 yes 的理由，每個引用看得到的字"],
 "red_flags": ["讓你想略過的地方"], "read_on": "往下看／略過"}
```

判讀：

| 項目 | 通過條件 |
| :--- | :--- |
| 職稱、公司、年資 | 三項都答對（對照履歷原文；年資差 ±1 年內算對） |
| can_do | 「是」，且依據引用的是成果或職稱，不是自我描述 |
| yes_reasons | ≥ 2 個，且至少 1 個與想傳達的訊息（步驟 3 essay 的「yes 理由」）一致 |
| 校準 | C 級同儕應「略過」或 yes 理由 ≤ 1；否則這輪不可信 |

## B. 盲審輸出 JSON（取代 2026-10-09 資料包的〈請輸出〉段）

```text
## 請輸出（只輸出一個 JSON，不要其他文字）
{
 "hr": {"候選人A": [H1 到 H10 各 1-5 分的整數], ...共 6 位},
 "hm": {"候選人A": [M1 到 M10 各 1-5 分], ...共 6 位},
 "rank_overall": ["最想約面試的候選人", "...", 依序 6 位],
 "pairwise_notes": "一句話：第一名勝過第二名的原因",
 "triage": {"候選人A": {"title": "", "company": "", "years": "", "yes_reasons": ["…"], "read_on": "往下看／略過"}, ...共 6 位},
   （先只看每份的上方 3 行與每行開頭，像 6 秒掃描那樣作答，再做完整審查）
 "objective": {"候選人A": {"answers_can_do": "是／否", "evidence": "摘要中回答『能不能做這份工作』的句子"}, ...共 6 位},
 "xyz": {"候選人X": [{"bullet": "條列前 15 字", "X": true, "Y": true, "Z": true, "type": "成果／職責／只有做法"}]},
   （只針對篇幅最長的 3 位，逐條標）
 "cut": {"候選人X": ["與目標職缺無關、建議刪除的段落或條列（引用前 15 字）"]},
 "interview_questions": {"候選人X": ["8 個最可能追問、針對該份履歷具體內容的問題"]}
   （只針對篇幅最長的 3 位）
}
```

## C. 報告彙整（寫進 `runs/<日期>/report.md`）

| 指標 | 怎麼算 | 用途 |
| :--- | :--- | :--- |
| 初篩通過率 | A 段三項答對且「往下看」的輪數 ÷ 5 | 版面是否撐得過 6 秒 |
| 平均 yes 理由數 | A 段 yes_reasons 個數平均，另記與 essay「yes 理由」一致的數量 | 第一屏是否傳達了想傳達的事 |
| XYZ 完整條列比例 | B 段 xyz 三格皆 true 的條列 ÷ 總條列 | 成果寫法 |
| 職責條列數 | B 段 type＝職責 | 應為 0 |
| 只有做法的條列 | B 段 type＝只有做法，每段 ≤ 1 | 交付鏈例外是否用過頭 |
| 建議刪除 | B 段 cut，5 輪中 ≥ 3 輪出現才列 | 相關性刪減 |

規則同 v3：5 輪平均與波動；**兩版差距小於波動不算進步**；對照組或 C 級同儕沒排在預期位置，這次評分不可信。
