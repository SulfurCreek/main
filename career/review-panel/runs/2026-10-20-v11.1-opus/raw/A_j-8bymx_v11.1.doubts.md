# A_j-8bymx_v11.1｜審查者的質疑與評語（claude-opus-5-5）

## 審查者的質疑

- [主管]「規劃 KOOL 網紅媒合平台，訪談商家的行銷單位」→ 探索做得像樣，但我要的是「完整 0 到 1」：KOOL 到底有沒有上線、上線後看了什麼、改了什麼？只看到付費功能上線，平台本體的驗證與迭代不見了 → 面試追問 → 要打消疑問需看到：KOOL 上線時間、首批商家或網紅數、上線後依回饋調整的一個具體例子
- [主管]「還原原價後，iOS 非續訂營收較原價期減 65%」→ 同一個價格前後差 65%，這多半不只是價格效果，季節或其他因素也有影響。他怎麼從這組數字得出「採用低價」？ → 面試追問 → 要打消疑問需看到：還原期 Android 對照組的同期變化，或團隊排除干擾因素的方式
- [HR]「具基本 HTML／CSS 與資料庫知識」→ JD 明寫要「基本 SQL」，這裡只寫資料庫知識，取數又是靠資料庫管理人員，看不出他自己會不會寫查詢 → 面試追問 → 要打消疑問需看到：自己寫 SQL 查詢的情境（查什麼、用來做什麼決定）
- [主管]「考量第一名切換帳號功能複雜度高，先推進第二名、已有規劃基礎的搜尋結果頁」→ 這句是真的在做取捨，有依據、有被延後的選項。我們要跟業務、營運、財務對齊優先序，就需要這種人，雖然停車／MaaS 領域完全沒碰過 → 仍然約談 → 要打消疑問需看到：說明雙邊媒合（商家／網紅、廠商／求職者）的經驗怎麼套用到停車場業者與車主
- [HR]「以 Claude Code、Antigravity 的 AI Agent 協作完成日常規格、資料整理與分析」→ 這和 JD 的 AI 工作流程化很吻合，還建了共用 skill，加分；但 JD 第一個講的是「快速做出原型」，這裡沒提到 → 面試追問 → 要打消疑問需看到：一個用 AI 產出可互動原型的案例，以及這個原型拿去驗證了什麼

## 評語

**結論**：interview｜Level 7（±1）｜取捨與規格能力足夠（「先推進第二名、已有規劃基礎的搜尋結果頁」），完整 0 到 1 與 SQL 待確認。

**做得好**

1. 1111 第四點｜「考量第一名切換帳號功能複雜度高，先推進第二名」｜JD 要求把痛點整理成優先序，這句有依據、有被延後的選項，能直接對應。
2. 尚凡第三點｜「以售價不變的 Android 作對照，依序測試原價、降價與還原原價」｜對照組實驗設計符合 Growth／數據分析加分項，也證明他懂定價。
3. 專業技能 API 協作｜「涵蓋簽章驗證、時間戳與防重放、錯誤碼、頻率限制及 JSON 欄位規則」｜具體回應「理解 API、JSON」這項必要條件，比只列名詞可信。

**可改進**

1. 尚凡第一點｜「規劃 KOOL 網紅媒合平台，訪談商家的行銷單位」｜requirement｜interview_follow_up｜JD 必要條件「完整 0 到 1」只算部分支持，主管會花面試時間確認｜補 KOOL 平台本體的上線時間、首批規模、上線後依回饋做的一次調整（只寫實際發生的）。
2. 專業技能｜「具基本 HTML／CSS 與資料庫知識」｜requirement｜interview_follow_up｜SQL 是明文必要條件，目前看不出程度｜若曾自己寫 SQL 查詢，寫出用途與情境；沒有就維持原句，面試時說明。
3. 尚凡第三點｜「還原原價後，iOS 非續訂營收較原價期減 65%」｜measurement｜interview_follow_up｜數字解讀不直覺，會讓人懷疑結論的依據｜補還原期 Android 對照組的變化，或用一句話說明採用低價的判斷依據。
4. 尚凡第四點｜「規劃 Peach App 由內購轉向網頁付款」｜readability｜editorial｜Peach 第一次出現，讀者對不上前文的「訂閱制內容 App」｜在公司說明或該句註明 Peach 是哪一類產品。
