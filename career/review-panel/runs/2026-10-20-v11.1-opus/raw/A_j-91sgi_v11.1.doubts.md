# A_j-91sgi｜v11.1｜claude-opus-5-5

## 審查者的質疑

- [HR]「依公司公開資料，JustDating 曾長期位居台灣約會類暢銷榜第一」→ 摘要和經歷講了兩次，但我們要找的是支付 PM，這句跟我們的職缺沒有直接關係，反而把金流經驗擠到後面。 → 面試追問 → 要打消疑問需看到：摘要前段就點出與支付相關的經驗（金流導入、付款管道、實收試算），哪一段最貼近錢包產品。
- [主管]「規劃 Peach App 由內購轉向網頁付款，推進智冠金流串接」→ 這是全份最接近我們工作的一條，結果數字也漂亮；但「推進」到底是寫串接規格、處理對帳和付款失敗，還是只負責跟窗口協調？ → 面試追問 → 要打消疑問需看到：本人寫的串接規格或驗收案例範圍（失敗、退款、對帳等例外怎麼處理），以及工程端由誰實作。
- [主管]「還原原價後，iOS 非續訂營收較原價期減 65%，團隊依結果決定採用低價」→ 還原成原價卻比原價期少了 65%，這不像價格效應，比較像別的因素干擾；這樣推出「採低價」我會想先確認邏輯。 → 降低信任 → 要打消疑問需看到：還原期 Android 同期的變化或已知干擾（排名、季節、活動），以及做決定時看的是哪個指標。
- [主管]「涵蓋簽章驗證、時間戳與防重放、錯誤碼、頻率限制及 JSON 欄位規則」→ 對理解 API 是好訊號，正面但保留：放在技能區，沒對應到哪個專案，不知道是本人議定還是旁聽工程討論。 → 仍然約談 → 要打消疑問需看到：一個具體串接案例，說明本人提出或決定了哪一項規格。
- [HR]「現任 1111 企業端招募系統 Product Owner，負責新版規劃與既有服務迭代」→ 近四年是 B2B 招募系統，跟高頻 C 端支付的節奏差很多；支付經驗停在 2021 年。 → 面試追問 → 要打消疑問需看到：本人說明為何轉向支付領域，以及有無銀行或公部門對接經驗。

## 評語

**結論**：interview｜Level 7｜必備三項皆有證據，「推進智冠金流串接」與定價實驗對支付職缺有用，但支付經驗偏舊、銀行對接未呈現。

### 做得好

1. 尚凡經歷 Peach 條｜「網頁付款占營收由 24% 升至 80% 以上」｜有期間與起訖值，直接對應支付與付款管道轉換。
2. 思維特經歷 CodaPay 條｜「整理各管道的抽成、稅、手續費與撥款週期，完成實收試算」｜顯示理解金流成本結構，並據以決定方案，是錢包產品需要的商業判斷。
3. 1111 經歷第 1、4 條｜「優先整合兩套系統，延後職缺匯入新功能」｜取捨、延後項目與依據都寫出，對應 JD 的產品規劃與團隊協作。

### 可改進

1. 尚凡經歷 Peach 條｜「規劃 Peach App 由內購轉向網頁付款，推進智冠金流串接」｜ownership／requirement｜interview_follow_up｜這是本職缺最關鍵的一條，主管會在面試花時間確認本人範圍｜補本人定義的串接規格或驗收項目（付款失敗、退款、對帳），並在首次出現時補一句 Peach App 是什麼產品。
2. 尚凡經歷定價實驗｜「還原原價後，iOS 非續訂營收較原價期減 65%」｜measurement｜interview_follow_up｜推論鏈看起來斷裂，可能降低對整份數字的信任｜補還原期 Android 同期變化或已知干擾，並寫明採低價看的指標；沒有資料就不要補數字。
3. 尚凡經歷 Juicy 條｜「主導接續產品 Juicy 推出，協調跨團隊工作並配合行銷導流」｜ownership｜interview_follow_up｜「主導」缺具體決定，DAU 成長和導流的貢獻分不開｜補一個本人做的關鍵決定（例如帳號或訂閱的承接方式），DAU 標明為團隊成果。
4. 專業摘要｜「具備訂閱與付費機制、定價實驗及企業流程規劃經驗」｜requirement｜editorial｜投支付職缺時，摘要沒有把金流導入、付款管道、銀行／合作夥伴對接放在前面｜投遞版調整摘要順序，凸顯金流相關經驗；有銀行或公部門對接經驗再補，沒有就不寫。
