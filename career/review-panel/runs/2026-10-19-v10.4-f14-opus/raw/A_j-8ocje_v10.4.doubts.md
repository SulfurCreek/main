## F4.3 評語

**結論**：interview／Level 7——「議定查詢 API 的簽章驗證、時間戳、錯誤碼」與舊系統改版案例足以約談，Jira 與法遵未呈現。

**做得好**
1. 1111 第6條｜「議定查詢 API 的簽章驗證、時間戳、錯誤碼、頻率限制」｜直接對應「熟悉API規格」與銀行／平台串接職責。
2. 1111 第1條｜「在業務後台與底層資料庫維持不變的限制下」｜展現技術可行性與系統架構關連的考量，符合必要條件。
3. 1111 第4條｜「先推進第二名的搜尋結果頁，延後第一名的切換帳號功能」｜排序依據清楚，對應開發時程規劃。

**可改進**
1. 專業技能｜「使用 Trello 及內部專案系統維持 Roadmap」｜requirement｜interview_follow_up｜Jira/Confluence 為明文必要，HR 可能卡關｜若有實際使用經驗補上工具名與用途；沒有則不要寫。
2. 專業技能｜「Figma、Axure RP、Notion」｜requirement｜interview_follow_up｜Axure 無使用情境｜在原型相關條目註明以 Axure 產出何物。
3. 1111 第6條｜「與外部合作夥伴及工程議定查詢 API」｜ownership｜interview_follow_up｜主管無法判斷本人深度｜補本人負責的條款範圍與上線狀態。
4. 1111 第1、2條｜「登入、首頁等功能於 2025/10 上線」｜measurement｜interview_follow_up｜缺上線後成效，JD 重視迭代｜若有上線後問題件數或使用變化可補，無則補一次依回饋調整的事實。
