## F4.2 審查者的質疑

- [HR]「近 10 年 PM 經驗，經手 6 款產品」→ 年資與產品數都夠，但我們要的是 0 到 1，不是經手數。 → 仍然約談 → 要打消疑問需看到：哪一款是本人從探索到上線再迭代的完整負責。
- [主管]「規劃 KOOL 網紅媒合平台…參考 Airbnb 與交友平台的媒合方式」→ 最像 0 到 1 的一段，但只寫到設計與上線，驗證和上線後怎麼改完全沒有。 → 面試追問 → 要打消疑問需看到：上線時間、早期驗證方式、上線後依什麼數據或回饋調整了什麼。
- [主管]「以 Claude Code 建立共用 skill」→ 方向對我們胃口，但 skill 做什麼看不出來，也沒提用 AI 做原型。 → 面試追問 → 要打消疑問需看到：一個 skill 的用途與省下的工作，或用 AI 產出的原型樣本。
- [主管]「先推進第二名的搜尋結果頁，延後第一名的切換帳號功能」→ 很少人寫得出不照票數排的理由，正面；但兩案都還在開發，看不到結果。 → 仍然約談 → 要打消疑問需看到：上線後是否驗證了這個排序判斷。
- [HR]「基本 HTML／CSS 與資料庫知識」→ 必備寫明基本 SQL，這裡只說資料庫知識、取數靠 DBA。 → 面試追問 → 要打消疑問需看到：自己寫過的查詢用途或現場小題。

## F4.3 評語

**結論**：interview／Level 7——「議定查詢 API 的簽章驗證…JSON 欄位規則」等多案例支持面試，0 到 1 驗證、SQL 待確認。

**做得好**
1. 1111 第一條｜「透過實測、工程驗證及維運與稽核訪談，還原缺乏文件的主副帳號權限與計費規則」｜對應 JD 與業務、客服協作整理痛點並設計技術方案。
2. 1111 第四條｜「以全國業務投票為排序依據，並考量開發複雜度與規劃準備程度」｜直接回應「對齊優先序」，取捨依據清楚。
3. 尚凡第三條＋思維特第二條｜「以售價不變的 Android 作對照」「完成實收試算」｜對應加分項支付與數據分析，且有對照組設計。

**可改進**
1. 尚凡第一條｜「規劃 KOOL 網紅媒合平台，從案主與網紅兩種角色釐清需求」｜requirement｜interview_follow_up｜必要條件「完整 0 到 1」只能部分支持｜補上線時間、驗證方式、上線後迭代依據與任何採用結果（不需編數字，質性亦可）。
2. 專業技能｜「基本 HTML／CSS 與資料庫知識」｜requirement｜interview_follow_up｜SQL 為明文必要，面試會被考｜若實際寫過查詢，明寫 SQL 與用途。
3. 專業技能｜「以 Claude Code 建立共用 skill」｜requirement｜interview_follow_up｜JD 首重 AI 做原型，現只有流程化線索｜補 skill 解決的工作，以及是否用 AI 做過原型。
4. 尚凡第四條｜「網頁付款占營收由 24% 升至 80% 以上」｜measurement｜editorial｜占比不等於營收或費率效益，主管會追問｜補同期總營收或手續費節省的脈絡（若有）。
