推論的做事流程（多個案例共通）：

```text
第一線訊號（客服反映、工單、事件）→ 查根因（資料盤點、競品實測、法規）→ 定規則與取捨（不強迫、分階段、先痛點）
→ 對齊（法務稽核、業務投票、副總匯報）→ 規格（需求 → 系統分析 → 流程與畫面 → PRD 與 Prototype）
→ 驗收（QA、UAT、客服封測）→ 上線（離峰、分階段、向客服說明）→ 依回饋調整
```

自傳戰役首選（推論）：**求才系統改版**——接手前任規劃、拆三階段、第一階段含登入時遇上千組重複 E-mail、選擇不強迫修改、離峰切換約 1.5 小時、上線前客服封測。同時涵蓋前三項價值觀，事實完整。
