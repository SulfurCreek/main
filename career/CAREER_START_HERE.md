## 1. main 嚴格唯讀與存取邊界

main 指分支名稱，不是 repo 名稱，也不是預設分支的代稱。

main 含有使用者工作檔案。只有具備讀取授權的代理，才能在任務必要範圍檢視內容、歷史及差異。
「唯讀」不代表所有代理都可以讀取；Codex 另受其 AGENTS.md 的讀取限制。

禁止：
- 新增、修改、刪除或重新命名 main 中的檔案。
- 對 main 執行 commit、merge、rebase、cherry-pick、reset 或 push。
- 透過 API、PR 合併、Actions 等方式間接更新 main。
- 未經明確授權，將 main 工作資料複製或發布到其他分支或外部服務。

入口文件本身也不得寫入 main。
只有使用者明確指名允許修改 main 並指定範圍，才能例外處理。

寫入前確認：
1. Repo、目前分支、目標分支及 commit。
2. 適用的代理指令與路由。
3. 使用者授權及可寫路徑。
4. 若目前位於 main，改至允許的工作分支，不在 main 留下修改。

本文件不構成 GitHub 層級的權限控制。

## 3. 任務入口與 Claude／Codex 讀取責任

### Claude 主代理

Claude 負責：
- 讀取事實庫、最新裁定及應徵工作卡。
- 閱讀完整 JD 與實際選用履歷。
- 解決來源矛盾。
- 將下游需要保留的事實、數字、限定詞與必要定義，
  編譯進上游草稿及 LOCK_ENTITIES／LOCKED。
- 維護 career/applications/<職缺代碼>.md 的追蹤與交接進度。

工作卡記錄來源、選用版本、應徵狀態／時間、面試安排、
產出文件、已確認決策、未決問題及下一步。
未知資訊保持待確認，狀態變更保留歷史。

### Codex

Codex 以 Claude 指定 commit SHA 的完整上游草稿，
及其中 LOCK_ENTITIES／LOCKED 為唯一事實基準。

Codex 不自行讀取 library、applications 或 SKILL.md 補充事實。
如遇缺漏、歧義或矛盾，提出具體上游修正要求，不自行補造。

完整閱讀義務不等於擴張資料存取權：
Codex 應完整閱讀獲准的上游草稿與下游候選成品，
不能以摘要或局部 diff 取代。

新 session、恢復或切換任務時，重新確認入口及指定交接版本。
Codex 透過交接材料取得進度，不讀取受限工作卡。

## 4. 完整閱讀與執行證據

Claude 與 Codex 均須理解完整成品，不能因修改責任分工而只看一部分。

### 修改前

Claude 完整閱讀所需事實、完整 JD 與本輪履歷。
Codex 完整閱讀鎖定 SHA 的上游草稿與既有下游版本。

確認：
- 整體定位與各段用途。
- 主要案例、數字、必要限定詞。
- 名稱首次出現的定義。
- 各欄位是否重複背景或互相矛盾。

### 修改時與修改後

每個修改檢查原意、責任範圍、事實強度、時序、
案例比重、首次定義及跨欄連動。

修改後重新完整閱讀候選成品。
工具輸出截斷或缺頁時補讀，未補齊不得宣稱整體完成。

### Proof of Execution：每次修改交付必附

① 子代理盲審原始挑刺摘要，以及逐項三分類處置表：
- 保留問題原意與位置，不把未處理項目從摘要刪除。
- 已修改項附 Before → After。
- 不採納項附具體裁定依據。
- 受鎖定阻擋項附可複製的上游替換指令。

② 跨欄連動檢查結果：
逐一檢查簡介、經歷、專長、自傳、專案，
確認沒有重複背景堆疊、定義缺口或事實矛盾。
有重複時記錄實際改動；保留時說明各欄不同用途。
不適用的欄位明確標示，不虛構已檢查內容。

僅填版本號或宣稱「已讀全文」不算完成。
以上為可供覆核的執行證據，不宣稱能技術上保證代理確實閱讀；
仍需透過成品、原始評閱與修改對照檢驗。

## 5. 固定交接、修改權限與終審裁決

流程：
Claude 上游
→ 固定 SHA 交接
→ Codex 下游潤飾
→ Gatekeeper Exit 0
→ 隔離盲審
→ 三分類處置及必要修改
→ 新候選版本 Gatekeeper Exit 0
→ Claude 主代理終審
→ 更新交接與選用版本。

每輪固定上游、下游的分支／路徑／完整 commit SHA。
不得僅指定「最新」。
上游更新不得默默混入；更換基底須記錄新版本及原因。
舊版評閱不能自動作為新版通過證據。

### 修改權限

Claude 負責：
- 事實編譯、選材與職缺定位。
- 刪除整個案例或改變整體定位。
- 調整上游 LOCKED／LOCK_ENTITIES。

Codex 負責且必須直接執行：
- 壓縮跨欄重複的背景解釋。
- 調整語序、節奏與銜接。
- 突出各段不同用途。
- 在不改變事實、限定詞及案例選材的前提下完成結構調整。

Codex 不得以「不得重新選材」為由拒絕跨欄去重。
若必要修改確實碰到 LOCKED／LOCK_ENTITIES，
使用三分類中的「受鎖定阻擋」，提出精確上游替換指令。

### Final Arbiter 與防乒乓紅線

Claude 主代理是跨輪次盲審衝突的最終裁決者。
裁決須服從事實、使用者明文裁定及鎖定約束，不能自行改寫它們。

必修（Blocker）僅限以下四類客觀硬傷：
1. 事實／數字／限定詞錯漏。
2. 首次提及未定義，造成概念偷跑。
3. 同段內明顯重複造句。
4. 首句無主詞被動語態，或違反適用 verify_*.py。

下列盲審要求必須歸入「🔒 不採納」：
- 跨輪次 A↔B 語序搖擺。
- 在功能尚未定義前，把合規驗收或被動結果搬到句首。
- 刪除強制限定詞。
- 純主觀同義換詞。

記錄具體依據後，對該爭議立即 Convergence Stop，
禁止繼續往返改寫。若該輪只剩上述爭議且無未解 Blocker，
停止該輪修稿；不得用收斂作為跳過其他硬傷的理由。

非 Blocker 不等於可以只列建議。
可自行修復的表達、節奏與跨欄重複問題，仍須直接改入成品。

## 6. 隔離盲審與強制三分類處置

### 盲審子代理的唯一角色

模擬未讀過內部資料的陌生 HR／Hiring Manager。

盲審子代理只准取得：
- 完整候選成品本身。
- 目標職缺 JD（有目標職缺時）。

禁止提供：
- career/library/ 事實庫。
- 內部寫作規則、SKILL.md 或主代理檢查表。
- 內部交接單、鎖定詞清單、修稿歷程。
- 作者身分、另一側評語或過往裁決。

如內部標記嵌在候選檔中，提供不含標記的對外呈現版本（於派發子代理之 Prompt 中直接剝除 HTML 註解，或讀取既有對外成品檔，不在 repo 新增臨時檔案）；
不可藉移除標記刪除成品正文或改變實際文字。
準備者保留其與候選 SHA 的對照，不交給盲審者。

評閱使用不曾參與寫稿、未讀內部資料的乾淨子代理。
兩邊均評閱完整成品，不拆成只看局部。
A/B 比較交換呈現順序；回收前不得互看評語。
無法達成隔離條件時，標示為非盲測，不冒稱盲測完成。

盲審檢查陌生讀者能否理解與信服。
事實、數字、限定詞與鎖定詞核對，由適用 Gatekeeper
與具備相應存取權的主代理負責，不把內部答案餵給盲審。

### Gatekeeper

104 履歷：career/scripts/verify_polish.py
自我推薦信：career/scripts/verify_letter.py
LINE 英文履歷：career/scripts/verify_line_profile.py

對應任務進盲審前及交付前均須 Exit 0，並對應實際候選版本。
沒有通過證據，不得進入下一關或標示可交付。

### Disposition Matrix：每項挑刺只能有一種處置

✅ 已直接修改入稿
- 適用所有可自行修復的表達、節奏及跨欄重複問題。
- 必須附 Before → After 與跨欄連動確認。
- 禁止只寫「建議修改」卻不改成品。

🔒 違反事實／本人明文裁定而不採納
- 附具體事實、裁定或防乒乓規則依據。
- 對屬於防乒乓紅線的項目立即收斂，禁止換詞反覆重開。
- 不得用本分類掩蓋可自行修復的問題。

⛔ 受上游 LOCKED／LOCK_ENTITIES 阻擋
- 指明鎖定區塊／詞、原文、衝突與所需修改。
- 附可直接複製的上游替換指令。
- 不得寫成「請上游看看」等不可執行交辦。
- 不得擅自突破鎖定。
- 未解 Blocker 仍阻擋交付，不能因已歸類就視為解決。

主代理取得盲審結果後，依第 5 節 Blocker 定義、
三分類與 Final Arbiter 規則處理。
不將內部裁決或修改答案回餵原盲審者，污染後續判斷。

## 7. 修後驗收與交付

每次修改後：
- 執行對應 Gatekeeper，取得新候選版本的 Exit 0。
- 完整閱讀新成品。
- 補齊 Before → After 及跨欄連動結果。
- 確認所有 Blocker 已解決。

改動事實、數字、選材、主要結構或定位時，重新評估整體影響；
需要再次盲審時使用符合隔離條件的新評閱者。
局部複查不能標示為整份成品重新通過盲審。
不得以固定輪數、收斂或三分類完成為由放行未解硬傷。

交付附：
- 上游／下游 SHA 與實際選用版本。
- Gatekeeper 指令、Exit Code 及對應版本。
- 盲審原始挑刺摘要。
- 強制三分類處置表。
- 簡介／經歷／專長／自傳／專案跨欄檢查結果。
- 未決事項及下一步。

區分本地修改、提交、推送、驗證通過與實際選用，
不得混為同一個完成狀態。

## 9. 第三方審查指令
