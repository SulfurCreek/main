# Resume Gen｜接收與協作指引

這份檔案供接收端辨認本封存包的使用方式。若既有專案已有 AGENTS.md、CLAUDE.md 或人物參考，不要以本包整份覆蓋；先核對、保留來源，再整合相同用途的資料。

## 接收時

- 先讀 README.md、handoff/01_project_instructions.md、handoff/02_current_state.md。
- 本次任務是遷移封存；不要因解壓縮就改稿、定版、選最新版本為底稿或重新評分。
- project_state.json 記錄觀察到的狀態；active_resume 為 null 時，下一次編輯依使用者指定版本開始。
- 人物敘事參考讀 reference/context/about-me-resume-gen.md；履歷數字與正文依本人指定稿。歷史文字提案不自動成為已確認事實。
- 原始檔保留不動；需要調整時在接收端既有專案流程建立修訂，留下來源與修改理由。

## Codex 與 Claude Code

- 共同讀取同一儲存庫中已指定的工作檔與狀態，不各自維護一份 current 或憑對話記憶補事實。
- 同一檔案同時只由一個工具寫入；另一個工具可讀取、檢查或提出建議。開始修改前確認檔案版本，提交前檢查是否被另一端改動。
- 有衝突時保留兩側差異、核對本人最新確認，再合併；不要用修改時間或模型名稱決定內容真偽。
- 每次完成後交付完整 Markdown，列重要改動與未定稿狀態；PDF 須另做實際版面檢查。

## 編輯底線

- 精簡要逐段核對意義。保留形成產品構想、說明判斷、動機、承接轉折、商業責任及必要限定。
- 工作經歷與自傳可用同一案例支撐不同用途，不能為避免重複而把自傳的思考依據刪除。
- 不把履歷變成工作報告、術語清單或防禦性查核紀錄；也不為縮頁消除必要的敘事前提。
- 原始 About Me 與技能快照未自動同步本次後續要求；詳見 handoff/07_editorial_preservation.md。

## 獨立驗證邊界

- 本專案負責編輯，不宣稱獨立評分。
- archive/historical_validation/ 與技能快照只供保存；不要自動執行、調整規準或用分數指導改稿。
- 真正送驗另建立乾淨資料包，只包含使用者指定的履歷、職缺與規準；不能把此完整遷移 ZIP 直接當成盲測輸入。
- 不把編輯對話、人物參考、歷史評分、修改理由或合成資料答案鍵給獨立驗證者。
