# Codex 與 Claude Code 的分工交接

本文件依據實際封存的 v10.4、v10.5、v10.7、v10.8 草稿與交接備註整理；描述可見的既有工作方式，再提出移交後的主要責任。沒有讀取使用者另一端的完整程式庫，因此不宣稱已核實該端所有檔案與實作。

## 可見紀錄支持的既有方式

| 原始紀錄 | 能確認的協作情況 |
| --- | --- |
| v10.4「給潤飾者的完整脈絡」 | 底稿標註只補事實、未潤飾，請在保留數字與限定詞下改成自然文字，並交付修改理由 |
| v10.4「Claude 定版備註」 | 記載正文採用 ChatGPT 修訂稿、Claude 核對既有資料並排成 PDF，且把更正記進既有 facts 檔 |
| v10.5、v10.7「Claude 定版備註」 | 記載採用 ChatGPT 文字稿並核對數字、時序、名稱及更正；說明當時為先做文案、再整合核對的流程 |
| v10.8「給潤飾者的說明」 | 提供尚未潤飾的六處改動與邊界，交由內容編輯改寫 |
| v10.9、v10.10 修訂說明 | 此端重寫／微調自傳，交付完整 Markdown 與歷史備註；未自行製作同版 PDF 或更新 About Me |

過往 Claude 曾在整合時調整文字；歷史備註的「正式版」僅描述當時版本，不能推成 Claude 永遠擁有最終決定權。

## 移到 Codex 後的主要責任

| 工作 | Codex（承接原 ChatGPT 這端） | Claude Code（延續既有整合端） |
| --- | --- | --- |
| 履歷與自傳 | 主責選材、論述、自然語氣、閱讀順序與語意保留，交付完整 Markdown | 整理需改的內容與來源，核對修訂是否越界，提出具體疑點 |
| 事實與資料 | 寫入正文前核對指定來源；新補充標示來源與確認狀態 | 主責整合本人已確認的來源與既有 facts 資料，保留期間、分母、歸因及進度 |
| About Me 與規則 | 主責編輯要求與人物敘事的理解；依授權提出或執行同步 | 與既有專案結構整合，避免重複有效副本；同樣須有本人授權 |
| 版本與 PDF | 檢查 PDF 是否保留指定文字的意義；提出閱讀問題 | 主責版本整合、排版產製、實際版面檢查與輸出追溯 |
| 職涯與面試 | 依本人需求主責釐清與追問，每輪聚焦一至兩項 | 提供已確認案例與資料，不從情緒或舊文案補結論 |
| 最終確認 | 依本人決定修改，不自行定版 | 依本人授權封裝版本，不因產出 PDF 就視為定版 |

兩端都是編輯協作者，都須守住事實與來源；主要責任的分配不是另一端免除核對的理由。本人仍是新事實、職涯方向與定版的確認者。

## 共用資料與交接

共用同一儲存庫與工作狀態，當前履歷、人物參考、事實來源分別指向唯一檔案。不要建立 Codex 專用 facts 與 Claude 專用 facts，也不要把某個模型的聊天記憶當成專案真實狀態。

同檔一輪只有一個寫入者，交接記錄檔案版本／hash、修改範圍、已改的意思、未解疑點與衍生 PDF 狀態。Claude 若因版面需要改動敘事，回到文案流程核對，不能在排版時默默刪掉思考過程。

本專案不擔任獨立驗證者。與履歷優化有關的兩端合作不能被稱為互盲評分；獨立驗證需另設乾淨輸入與新 context。歷史驗證資料完整保存，但不恢復以分數為改稿目的的舊指示。

完整可貼給 Codex 的指令見 04_codex_import_prompt.md。
