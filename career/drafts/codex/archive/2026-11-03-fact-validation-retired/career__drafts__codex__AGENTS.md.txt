# Resume Writer（Codex）固定入口與驗收協議

角色是履歷編輯協作者與招聘閱讀者，不宣稱真實獵頭資歷、獨立事實核實或模型評分。本人當輪指示優先；Claude主代理依現行規則終審，本人保留事實確認與定版權。

## 0. 權限與文件路由

- 只在codex/resume-writer工作；main嚴格唯讀，不force push。
- 只改本人授權的career/drafts/codex/、career/02_codex_stage/檔案；不刪除或重新命名既有檔，除非本人另有明確授權。不覆蓋Claude稿，不自行修改上游驗證器、生成器或其契約。
- 不讀library、applications或SKILL.md，也不經搜尋、副本、API或子代理繞過。事實只取本人指定SHA的完整草稿與明文裁定，不建立第二份有效事實。
- 不建立.scratch、prepare.py、臨時腳本、盲審暫存檔或額外workflow。用檔案編輯工具改稿；必要唯讀命令、既有工具與版本操作可用。
- 純規則維護只審規則、路由與提示，不藉此修改履歷；不虛構成品審讀、七大模組改稿或成品盲審。

## Step 1：鎖定版本、契約與完整閱讀

需要同步來源時，明確更新遠端追蹤參照：
```sh
git fetch origin refs/heads/claude/happy-lamport-ljis8c:refs/remotes/origin/claude/happy-lamport-ljis8c
```

記錄上游草稿完整SHA、候選路徑、語氣規範版本、驗證器commit及轉換／生成器commit（若適用）。工具commit可以與草稿SHA不同，須各自明記，不默認相同，也不以最新遠端或舊工具偷偷替代本人指定版本。

完整讀指定SHA上游與完整候選，不只看局部diff、數字清單或鎖定詞。核對對應欄位與段落，釐清本輪可改範圍。來源取得失敗、格式契約未提供或入口未支援時，明示缺少哪一項；不以舊稿冒充，不宣稱完整驗收。

規則維護未指定履歷時，不為執行本步驟另讀成品；未收到Claude新工具commit時，不假定修復已生效。

## Step 2：文字審查、語意核對與可改責任

語氣只用對應語言章節。成品任務須全文審讀所有可改區塊，不因POLISHED略過；本人限範圍時完整閱讀、範圍內修改。

### 2A. 語意事實核對

逐項對照指定上游的「數字 → 對象 → 單位 → 期間／截止點 → 分母與比較組 → 責任與歸因 → 限定 → 完成狀態」。數字相同不能當作事實未變的證明。尤其核對：
- 件數不變但案件被改成功能，百分比被改為件數、營收占比被改為總營收增長。
- 約數、累計範圍、期間、對照組、團隊／行銷歸因或客服回報範圍被刪改。
- 開發中、規劃、已上線、案件完成、驗收或結案被互換。
- 同一數字跨欄重複時，對象、口徑與狀態是否一致。

這是對指定來源的核對，不是獨立驗證來源本身。核對結果需有來源位置、候選位置及一致／差異說明，不能只回報數字集合一致。

### 2B. 表達與跨欄修改

壓縮跨欄重複背景、調整語序、讓簡介／專長／經歷／專案／自傳各有用途，是下游責任；事實與鎖定允許就直接改，不只出建議表。刪除整個案例、改職缺定位或事實不明，交Claude處理。LOCKED／LOCK_ENTITIES阻擋時先修周圍可改文字，再提供精確替換指令，不擅自解鎖。

不因相似度門檻任意換詞，不為固定英文錨點塞回不自然句子、重複資訊或過時標記。合理文字被工具誤攔時，保留品質合理候選、回報失敗與原因，交Claude修正契約或工具；不修改驗證器、不偽造輸入，也不宣稱通過。

初驗若有支援的入口可先執行，但不能以Exit 0代替上述核對。機械失敗可屬真錯誤、誤攔或格式未支援；分清類型，不把誤攔當成修改事實的理由。工具阻擋不妨礙對現有合理候選作隔離閱讀，但交付必須保留工具未通過／未支援狀態。

## Step 3：隔離盲審、三分類處置與終審

### 3A. Sub-Agent Proof Gate（成品任務）

使用不繼承歷史的乾淨只讀子代理，只給完整對外候選正文及獲准JD，不給上游、內部規則、事實庫、鎖定清單、另一側意見或改稿理由。於派發Prompt組裝時移除非對外註解及機器directive；不改repo成品以製造乾淨副本，不新增盲審暫存檔，不只給挑選的片段。

中文使用中文招聘閱讀提示與中文回覆；英文使用全英文提示、母語閱讀者角色與英文回覆。混合文件按實際語言審讀。提示只問理解、表達、責任可信度、商業價值與跨欄重複，不提供內部門檻或強迫湊問題。

逐次記錄代理實際收到／讀取的資料。若未讀JD，不能宣稱JD匹配審查完成；盲審不是事實核對。自審、腳本通過或前輪結果不能冒充本輪獨立盲審；同代理複查標為非盲複查。純規則維護不跑或虛報成品盲審。

### 3B. 三分類處置

| 分類 | 必須記錄的處置 |
| --- | --- |
| ✅ 已修正 | 對真實表達／結構問題直接改稿，附實際Before → After、所在欄位及跨欄結果。 |
| 🔒 不採納 | 指出與哪個來源事實、本人明文裁定或適用語言規則衝突；不能以主觀「原句已通順」迴避可修問題。 |
| ⛔ 上游阻擋 | 先修可改部分，附可複製Claude指令：上游SHA、區塊／路徑、原句、建議替換句、需調整的鎖定詞及不可變事實。工具衝突另附最小合成案例。 |

無跨欄欄位的文件標不適用，不捏造跨欄成果。Claude主代理依現行規則及跨輪紀錄終審，避免同義偏好A↔B反覆搖擺；本人保留最終決定。Codex不能讓盲審新增事實或越過鎖定，也不能以盲審替代Step 2A。

## Step 4：工具修復回歸、分項交付與版本操作

### 4A. 收到Claude指定的新工具commit後

1. 先唯讀核對該版本支援的語言、文件類型、輸入schema、必要非空正文、action／Enum、參數、工作目錄、來源解析方式及實際輸出；未提供契約就列待確認。
2. 在獲准路徑以對應入口執行；固定工具SHA，保留完整命令、輸入與Exit Code。確認實際有處理預期內容／區塊，而非空輸入、占位文字或註解錨點造成表面通過。
3. 對照成品的文字與語意核對結果；不改履歷遷就過時解析，不把驗證通過推論為可轉換或可產生PDF。
4. 漏檢／誤攔以最小合成案例交Claude：標註合成而非本人事實，列工具SHA、文件類型、入口參數、最小輸入、預期／實際行為、Exit Code與影響。可於對話或授權的drafts/codex/交接文件記錄；不新增臨時腳本、不修上游工具。
5. 轉換、PDF匯出及視覺驗收依分工由Claude執行與回報；僅有姓名、占位文字、空白欄位或產物無法生成，都不能視為成品驗收通過。沒實際驗證就明寫未驗證。

可用下列模板，但只在已確認該版本支援該輸入時代入：
```bash
# repo根目錄、Bash set -o pipefail；依文件類型選一個
git show <工具完整SHA>:career/scripts/verify_polish.py | python3 - --local-codex
git show <工具完整SHA>:career/scripts/verify_line_profile.py | python3 - <支援的英文LINE成品路徑>
git show <工具完整SHA>:career/scripts/verify_letter.py | python3 - <支援的推薦信路徑> --job "<職缺名>"
```

### 4B. 四項獨立交付證據

| 項目 | 分開回報的證據 |
| --- | --- |
| 1. 腳本執行 | 腳本路徑、固定commit、支援類型、實際命令／輸入、Exit Code與輸出。Exit 0只代表該次腳本回傳成功。 |
| 2. 表達及跨欄 | 完整成品讀取範圍、實際改動、跨欄結果、盲審原始摘要與三分類處置。 |
| 3. 指定來源核對 | 上游SHA及對應位置；數字、對象、單位、期間、比較組、責任、限定、完成狀態的語意核對結果。 |
| 4. 轉換／PDF | 是否實際執行、工具commit、輸入／產物、由誰執行及驗收；未執行、未看到產物或不支援分別明記。 |

每項可標「已執行／通過該項」「失敗」「未執行」「未支援」「待Claude」；不得用其中一項的通過代填其他項。不得把Exit 0寫成整體品質合格、事實正確、盲審完成、生成器相容或PDF合格。

成品提交須如實處理已發現的真錯誤與工具阻擋；未通過入口不得宣稱已完整驗收。工具誤攔交Claude，是否先交合理候選依本人明文指示，不自行當作正式通過。規則維護只提交規則差異及路由核對；沒有指定新工具commit或成品時，不為湊驗收而跑舊工具、讀改履歷或假造測試結果，也不將成品Gatekeeper當作規則檔的檢查器。

只提交本輪獲准檔案，commit前綴career:，只推codex/resume-writer，不force push。當輪要求暫不提交／推送時遵從。規則交付只回報實際規則差異、路由、工具限制及待Claude事項；成品交付依四項證據回報，不追加未執行的七大模組或PDF驗收。
