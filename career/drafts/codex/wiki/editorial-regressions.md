# 真實錯誤與檢查案例

這裡保存編輯錯誤及怎麼檢查，不取代 library 的事實。反例不是可貼入履歷的文案；來源若更新，回共用來源核對。使用流程見 [resume-editor](../skills/resume-editor/SKILL.md)。

| 案例 | 曾發生的問題 | 下一次怎麼檢查 | 依據 |
| --- | --- | --- | --- |
| E01 帶人案例 | 把「依文件規範、補資訊、檢查、判斷、交付」列成操作清單，讀者看不到主管為何介入 | 能否讀出同仁卡關、本人的方法調整與教導、同仁保留的判斷及已知結果；不以 AI 操作步驟取代帶人主線 | [本人指出的兩點與修訂](../2026-10-21-104-management-feedback-rewrite.md)；共用 About Me〈四〉 |
| E02 客戶回饋 | 「企業使用」主詞缺漏、「提案」未定義、「處理／安排處理」重複 | 先辨認企業客戶、招募系統、問題回報與改善建議，再說本人安排及追蹤什麼 | 同上 |
| E03 指標語意 | 將案件結案寫成交付，或把兩期比例變化當成個人造成的效率提升 | 指標名稱、事件、期間、分母、因果與歸因逐一對照來源；回覆、結案、功能上線、採用成效分清 | 同上；共用 facts-1111 與 evidence-cycle-time |
| E04 選材 | 事實正確就放正文，履歷變成內部工作交接與 roadmap | 每點能說出招募用途；只保留對外合適的背景、判斷、產出或成果 | [因果與 SweetRing 交接](../2026-10-21-resume-causal-logic-and-sweetring-handoff.md) |
| E05 過度補背景 | 為單點獨立，每點重複完整 KOOL 名稱及產品背景 | 單點與整段都讀；只補會影響理解的對象或情境，不能機械反覆加產品全名 | Career Move `dd3d9f1` 的 v11.2 整合註記；[前輪潤飾](../104-v11.2-polished.md) |
| E06 只修字面 | T1–T6、字數與 HTML 通過，仍把生硬的兩點原樣交出 | 分開記格式／事實與人工語意結果；看不出主要責任、用字搭配不當或像工作報告就繼續修 | [兩點修訂](../2026-10-21-104-management-feedback-rewrite.md) |
| E07 簡介過短或像自傳 | 為精簡丟掉商業經驗，或用完整做事流程開場 | 簡介讓人立刻辨認整體輪廓，案例留經歷、自傳；保留必要辨識度，不以縮字率選稿 | [摘要檢視](../2026-10-21-summary-review-and-rewrite.md)；共用規格 §5 |
| E08 特色與標準 tag 混用 | 用專長分類取代頂部特色，或重寫本人已定文字 | 分清個人特色與技能選項；Client／Business 及五個 chip 查指定稿，鎖定就逐字比對 | [特色交接](../2026-10-21-104-summary-chips-claude-handoff.md) |
| E09 SweetRing 範圍不足 | 只寫海外及支付，遺漏維運與功能優化 | 查 library 已確認職責；選代表案例，不必把所有附件都塞進正文 | 共用 facts-prior 最新 SweetRing 節；[案例交接](../2026-10-21-resume-causal-logic-and-sweetring-handoff.md) |
| E10 目標誤當成果 | 文件提示文案或目標被寫成已達成成效 | 區分規劃內容、主責、已上線、實測成效；確認上線不等於確認效益 | 同上；[QUESTIONS 的已回答事項](../QUESTIONS.md) |
| E11 推論責任升級 | 強動詞表把規劃、協作改成工程架構／獨立開發 | 動詞逐項對照事實；公司規模與團隊成果不變成個人成果 | 共用 decisions §1、voice-en §2 |
| E12 推送與同步混同 | 交接已推就說 About Me 已更新，已解決問題仍標待同步 | 讀回共用檔及提交，區分送出、採用、來源寫入、PDF；更新狀態入口 | [交接狀態](handoff-status.md) |
| E13 重複問答 | 問過的 KOOL、帶人方式、SweetRing 主責又重 grill | 問前查 About Me、open-questions、QUESTIONS 最新狀態；只問新資料造成的必要缺口 | 共用 About Me〈八／九〉；[QUESTIONS](../QUESTIONS.md) |
| E14 舊指令回流 | 封存技能的 Library ID、評分、Level、舊程式被當現行命令 | 先看 [技能狀態](skills.md)，封存只追溯；來源、動作與版本都需本輪授權 | [歷史研究分類](research-and-tools.md) |
| E15 版本混同 | 最高版號被當底稿，文字與 PDF 版本混用 | 本人指定優先；讀共用路由與稿件 hash，PDF 另核對，不能由檔名推定同版 | [歷史版本說明](versions.md)；[交接狀態](handoff-status.md) |
| E16 信件語氣 | 固定能力小標、英文說明句、敬上或被否決的結尾再次出現 | 直接向招聘者說相關經驗；不用寫作安排當內容；按本輪回饋與 voice-en 實讀 | [推薦信及待改核對](../2026-10-21-pacston-letter-and-pending-review.md) |
| E17 被動句與改寫比例 | 成品 15 次「由我」，為成果置前、單點歸因及字面改寫比例而倒裝，造成生硬重複 | 成果後直接寫主動動詞；省略預設本人主詞，保留團隊／同仁歸因。語感修正不為湊比例再倒裝；逐點與整段讀，數量及腳本通過不等於自然 | [A 方案修整與交接](../2026-10-21-stage-active-voice-handoff.md)；[語氣指南](../../../02_codex_stage/voice_style_guide.md) |

檢查結論需指向實際改動或保留理由，不只寫「全部通過」。表中案例是人工閱讀檢查；本區結構腳本不判斷這些語意。
