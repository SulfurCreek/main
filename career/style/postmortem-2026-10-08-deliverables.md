# 檢討：v4～v5.2 履歷遺漏 PM 交付鏈與產出文件（2026-10-08）

## 發生什麼
使用者指出：v4 之後的履歷看不到 User Journey Map、User Story、Use Case、SA、流程圖／循序圖、Wireframe、Prototype、Spec、QA 協作、上線計畫等產出與流程。這些在 `wiki/F01`、`F02`、`F05` 都有證據，早期 wiki 草稿（`resume-extract.md`）也有寫。

## 根因（依影響大小）
1. **把「少技術詞」擴大解讀**：使用者 10/06 說的是工程術語（HMAC、MECE、SSOT）太多。我把 PM 產出物名稱一起當成術語刪掉，沒有回頭確認範圍。
2. **V4 規則與事實衝突時沒停下來**：使用者提供的 V4 去潤飾規則寫「不寫 user story、蒐集需求」。這條原意是不要把日常勞動寫成成就，我卻照字面刪掉整條交付鏈，而且沒有列入「與事實衝突時以事實為準」的檢查。
3. **審查機制只獎勵數字與結果**：審查清單 v1、v2 都沒有「職能覆蓋」項目。每輪我都朝分數優化（結果先行、精簡、量化），產出物沒有數字，就一輪一輪被擠掉，而審查不會扣分。
4. **改稿以上一版為底，不回頭讀職能頁**：v4 以後都從前一版刪修，沒有再對照 F01–F15，遺漏一旦發生就一直沿用。
5. **研究結論套用過頭**：「資深 PM 寫影響力而非工作內容」被我解讀成不寫流程。實際上流程與產出物是證明「怎麼做到」的證據，不是職責清單。
6. **skill 本身也有舊內容**：`resume-craft` 叢集表仍寫 1,279 工單／88%、強動詞表仍有 Spearheaded／Architected，與 library 現行事實和裁定衝突。
