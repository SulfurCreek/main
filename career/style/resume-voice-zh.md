# 履歷語氣規範（繁中，從使用者 2026-10-05 潤飾稿萃取）

> 適用：104、Cake 等所有中文履歷、自傳、專案說明。平台欄位規格各自看 `../104/`、`../cake/`；語氣共用本檔。
> 事實與數字仍只能來自 `../wiki/`。語氣可以強，**事實不能誇大**——第 3 節的護欄優先於第 1–2 節。

## 1. 使用者偏好的語氣

| 特徵 | 做法 | 例 |
| :--- | :--- | :--- |
| 每條先下標題 | 粗體短標題（4–10 字）＋冒號，再接內容；標題後可加英文術語括號 | **建立單一事實來源（Single Source of Truth）：** … |
| 中英並列關鍵術語 | 專業詞第一次出現時中文＋括號英文，方便 HR 與 ATS 同時命中 | 世代分析（Cohort Analysis）、定價策略（Pricing Strategy） |
| 主動、結果導向的動詞 | 主導、統籌、制定、收斂、締造、實證、帶動、引導 | 「統籌 227 項 Roadmap」而非「負責 Roadmap」 |
| 先講商業意義再講做法 | 每段收在「對公司帶來什麼」：留存、變現、交付速度 | 「產品的終極目標是變現與留存。」 |
| 自傳分主題段 | 每段一個【小標】，三到四段：定位 → 技術與架構 → 商業與 AI → 前 90 天 | 【技術力與架構思維｜…】 |
| 句子連貫、有轉折 | 用「面對…，我…」「此外」「透過…，我讓…」串成敘事，不是條列碎句 | 「面對龐大的系統包袱，我主導了…」 |
| 自信但具體 | 形容詞後面一定接數字或具體做法 | 「卓越紀錄」後面接「半年 111 項、94% 準時」 |

## 2. 結構範本

1. **【核心能力與專業定位】**：3 條，每條「粗體標題（英文）：一句能力＋一個代表數字」。
2. **【工作經歷】**：每家公司 3–5 條，每條「粗體標題：情境 → 我做了什麼 → 結果數字」。
3. **【中文自傳】**：3–4 個【小標｜副標】段落，每段 ≤ 5 行。
4. **【英文自傳】**：3 段，第一段定位、第二段現職、第三段前職＋AI＋語言證照。

## 3. 護欄（比語氣優先）

| 不可以 | 原因 | 改法 |
| :--- | :--- | :--- |
| 寫證據沒有的形容 | 面試追問答不出來 | 只寫有證據的。註：求才新版**不可寫「零停機」**——使用者確認離峰時段停機約 1.5 小時；寫「離峰切換、停機約 1.5 小時」；E.1 訊息整併仍寫「向下相容的漸進遷移」 |
| 改變數字的意思（如「註冊數 +67%」寫成「註冊轉換率 +67%」） | 指標不同，被追問就破功 | 照 wiki 原指標名 |
| 把範圍放大（「14.9 萬家企業名冊」寫成「14.9 萬家客戶」；「維運工單」寫成「客服工單」） | 同上 | 照 wiki 原描述 |
| 產品標籤寫錯 | JD2（JustDating 2）、Juicy、KOOL 是自動續訂訂閱制 App；Peach 是個人頻道訂閱制 | 依此區分，不要混寫 |
| AI 腔字眼：intricate、exponential(ly)、realm、pivotal、showcasing、極度、無與倫比 | 易被判定 AI 生成（resume-craft 紅旗） | 換成具體動詞或刪掉 |
| 營收、分潤絕對金額 | 使用者保密決定 | 只寫比例與倍數 |
| 自傳、專案說明含姓名、電話、地址 | 104 明文禁止 | 刪 |
| 文中出現 `[cite: …]` 等引用標記 | 生成工具殘留 | 輸出前全文檢查刪除 |

## 5. 從使用者「多 AI 分析版」學到的寫法（2026-10-05，優先於第 1–2 節）

> 範本：`../104/resume-104-draft.md`。這是使用者認可的語氣基準，之後的中文履歷以它為準。

| 特徵 | 做法 |
| :--- | :--- |
| 開頭先給**專業摘要** | 一段定位（年資＋兩條主線＋核心強項），再接 4 條「**粗體標籤**：數字成果」——系統改版／交付與維運／成長與變現／AI 應用 |
| **核心能力**用關鍵字群 | 4 組粗體類別，每組一行關鍵字（不寫句子），方便 ATS 與 HR 掃讀 |
| 工作經歷**分組**而非長條列 | 每家公司下用 4–7 個粗體小標分組，每組 1–3 條短 bullet；一條只講一件事 |
| 數字一律**粗體** | 14 倍、24%→80%、227／111／94%、1,857、93% |
| 職稱兩行 | 第一行「公司｜正式職稱」，第二行「**1111 人力銀行招募系統 Product Owner｜管理 2 人**」 |
| 年資寫「近 10 年」 | 與 104 總年資 9~10 年一致，不寫「10 年」 |
| 相關性主張用「分析顯示」 | 世代分析是相關不是因果，寫「分析顯示…留存率較高」 |
| 流程寫「混合式」 | 「工程以階段式（Waterfall）開發，管理面以 Kanban、Daily Stand-up 與 Retrospective 追蹤與改善」 |
| 代表專案獨立一節 | 2–3 個，每個「名稱＋期間＋一段說明」 |
| 自傳收尾 | 「經歷補充與前 90 天」一節，放學經歷時序與加入後承諾 |
| 句子短 | 括號說明減到必要，少用「並」連三個以上動作 |

### Claude 檢查後修正的 3 處（再出現要照改）
1. 「約 50 項**大型**功能改版」→「約 50 項功能上線，**其中**大型改版涵蓋…」。50 項含 Footer、QR Code 等小項，全稱大型會被追問。
2. 「已完成兩階段內部測試」→「已進入第二階段內部測試」。第二階段測試期 2026/10/05–10/08，尚未結束；測試結束後可改回。
3. 專業摘要不放「停機 1.5 小時」：停機是細節，放工作經歷即可；摘要只寫「第一階段於 2025/10 完成切換」。
