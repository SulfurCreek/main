# 104 公開版去識別化

## 這個 skill 要解決的問題

使用者有兩份 104 履歷：
- **正式版**：完整內容，是唯一的內容來源。使用者只會更新正式版。
- **公開版**：給所有人看的版本。內容要跟正式版一樣，但**不能讓人看出使用者現在在 1111 人力銀行工作**（1111 是 104 的競爭對手）。

你的工作：每次執行時，用正式版的最新內容重建公開版，並套用下面的去識別化規則。

## 鐵則（違反任何一條就停止，回報使用者）

1. **絕對不能修改正式版。** 每次按「儲存」前，確認畫面上的履歷名稱是「公開版」。如果是正式版，不要儲存，立刻停止並回報。
2. **只做去識別化，不改寫。** 除了規則要求的取代與刪除，其他每一個字都要跟正式版完全相同。不要潤飾、不要摘要、不要調整語氣、不要新增任何文字或數字。
3. **不確定就問，不要猜。** 遇到規則沒寫到、你無法判斷的句子，把那句原文列出來問使用者，等使用者回答。不要自己決定。
4. **只處理目前任職的這一段。** 前公司（尚凡國際創新科技、思維特網路資訊、台灣新蛋）的名稱與內容全部保留，不去識別化。

## 執行步驟

### 步驟 1：確認公開版存在
- 在 104 履歷管理中找名稱為「公開版」的履歷。
- 如果沒有：用「複製履歷」把正式版複製一份，名稱改成「公開版」。
- 如果有：繼續下一步。

### 步驟 2：讀取正式版最新內容
逐欄讀取正式版以下欄位的完整文字，存成你的工作底稿：
個人簡介、個人特色、工作經歷（每一段的說明與標籤）、專長（每一張卡片的名稱、說明、標籤）、自傳、專案成就（每一案的名稱、說明、圖片）、求職條件的工作內容。

### 步驟 3：在工作底稿上套用去識別化規則（見下方「規則」）
- 先在底稿上改好，**還沒改到 104 頁面**。
- 改完後執行「步驟 5：自我檢查」的第 1～3 項。全部通過才繼續。

### 步驟 4：把底稿寫進公開版
- 開啟「公開版」，把每個欄位的內容換成底稿的內容。
- 每個欄位儲存前，確認履歷名稱是「公開版」。

### 步驟 5：自我檢查（每一項都要做，並把結果寫進回報）
1. 在公開版全文搜尋下列字串，每一個都必須是 **0 筆**：
   `1111`、`全球華人`、`求才`、`招募管理`、`冒用`
2. 把公開版和正式版逐欄比較：除了規則要求的改動以外，**沒有任何其他差異**。
3. 列出這次所有改動，格式：`[欄位] 原文 → 改成`（刪除寫成 `→ 刪除`）。
4. 下載公開版 PDF。

### 步驟 6：回報
回報內容：步驟 5 的四項結果、問使用者的問題（如果有）、做不到的地方（如果有）。

## 規則

### 規則 A：固定設定（每次都檢查）

| 欄位 | 公開版的值 |
| --- | --- |
| 工作經歷第 1 段（目前任職）的公司名稱 | `國內人力銀行平台`（如果 104 有「不公開公司名稱」選項，也勾選） |
| 工作經歷第 1 段的公司 logo | 不能顯示 1111 logo；移除不了就在回報中說明 |
| 專案成就中，圖片是 1111 logo 的專案 | 刪除圖片，素材欄留空 |
| 手機、E-mail、工作地點（如「台北市松山區」） | **保留，不要改**（本人 2026-10-25 決定） |
| 通訊地址 | 依 104 預設（104 會自動遮罩門牌） |

### 規則 B：固定取代表（先做這一步）

依序搜尋左欄字串，取代成右欄。

| 搜尋 | 取代成 |
| --- | --- |
| `1111人力銀行招募系統` | `人力銀行企業端招募系統` |
| `1111 人力銀行` | `人力銀行` |
| `1111人力銀行` | `人力銀行` |
| `我加入 1111，` | `我加入目前的公司，` |
| `1111 新版求才系統重整` | `企業端招募系統全面改版` |
| `1111 企業群組共同招募` | `企業群組共同招募` |
| `新版求才系統` | `新版系統` |
| `招募管理` | `招募系統` |

取代後，如果出現「企業端招募系統企業端招募系統」這類重複詞，刪掉重複的部分。

### 規則 C：會讓人認出公司的規模與事件（固定處理）

| 正式版出現 | 處理方式 |
| --- | --- |
| 「約 6 萬家活躍付費廠商」「6 萬家」 | 改成「數萬家付費企業客戶」，句子其他部分不動 |
| 含「冒用」的整個條列項目（帳號冒用事件） | 整條刪除 |
| 「15 張類別代碼表」 | 改成「類別代碼表」 |

### 規則 D：判斷新內容（規則 B、C 沒有涵蓋時才用）

正式版以後可能新增句子。對每一句，**依序問自己下面 4 個問題**。只要有一題答「是」，就要處理；四題都是「否」，就原樣保留。

**問題 1：這句有沒有直接寫出公司名稱或品牌？**
- 例：`1111`、`全球華人`、`招募管理`、`求才系統`、`1111 App`
- 是 → 用規則 B 的方式取代成不帶品牌的說法（例如「人力銀行」「企業端招募系統」）。

**問題 2：這句有沒有只屬於 1111 的內部名稱？**
- 判斷方法：這個名字如果拿去 Google 搜尋，會不會只找到 1111 的東西？會 → 是內部名稱。
- 例：「新版求才系統」是內部專案名稱 → 是。
- 例：「AI 推薦人才」「職缺工作說明生成」是一般功能描述，各家都有 → 否，保留。
- 是 → 改成一般描述（例：「新版求才系統」→「新版系統」）。不確定 → 問使用者。

**問題 3：這句有沒有公司層級的規模數字，可以拿去比對出是哪一家？**
- 判斷方法：數字描述的是「整間公司／整個平台」（例：全站廠商數、會員數、營收），還是「使用者自己負責的工作成果」？
- 整間公司的規模 → 是 → 改成不精確的說法（例：「6 萬家」→「數萬家」）。
- 使用者自己的工作成果 → 否，保留。例：「840 件建議完成 743 件（88%）」「結案比例由 52% 升至 79%」「約 70 項主要功能」「199 件」「55 件」都是使用者的工作成果，**保留**。
- 不確定 → 問使用者。

**問題 4：這句是不是在描述公司的負面事件或內部機密？**
- 例：資安事件、系統被攻擊、帳號被盜、客訴事件、內部權限代碼、內部單位名稱、同事姓名、合作廠商名稱。
- 是 → 整條刪除，並在回報中列出。

**範例（照這個方式推理）：**
- 「現任 1111人力銀行招募系統 Product Owner」→ 問題 1 是（有 1111）→ 規則 B →「現任人力銀行企業端招募系統 Product Owner」
- 「與資料科學團隊定義使用情境與驗收標準」→ 四題都否 → 保留
- 「2026/03–04，十多家廠商的招募帳號接連遭冒用登入……」→ 問題 4 是（資安事件）→ 整條刪除
- 「截至 2026/Q3，約 70 項主要功能已上線」→ 問題 3：是使用者的工作成果 → 否 → 保留

## 常見錯誤（不要犯）

- ❌ 順手把句子改得更通順。→ 只做規則要求的改動。
- ❌ 把前公司（尚凡、思維特、新蛋）也去識別化。→ 前公司全部保留。
- ❌ 把使用者的工作成果數字刪掉或改模糊。→ 只有公司規模數字要改。
- ❌ 在正式版上修改。→ 每次儲存前確認是「公開版」。
- ❌ 遇到不確定的句子自己決定。→ 列出來問使用者。
