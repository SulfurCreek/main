# 104coverletter：104 自我推薦信（逐職缺客製）

> 維護：Career Move。依據：`career/104/cover-letter-research.md`（本人 2026-10-20 提供）。
> 與 `resume-craft/references/cover-letters.md` 的分工：那份是 A4 一頁的完整書信（Email／官網上傳）；**本 skill 只管 104 等平台「應徵時填的推薦信欄位」**。

## 1. 輸入

| 項目 | 來源 |
| :-- | :-- |
| 職缺 | 本人給的職缺代碼或名稱 → `career/review-panel/jd/routing.tsv` 找 code、公司、職稱；JD 原文：`career/targets/jobs.md`（必要時 `review-panel/jd/full/<code>.md`、`light-cards.md`） |
| 該職缺的驗證結果 | `review-panel/runs/` 最新一輪對該 code 的 `apply_hook`、`top_gap`、F 層 doubts（可用來選要打的亮點與要避開的缺口） |
| 事實 | `career/library/`（先 `INDEX.md`、`decisions.md`、`superseded.md`、`about-me.md`）；現行履歷 `drafts/<版本>/resume-<版本>.md` |
| 分級 | 本人指定「主力」或「一般」；沒說就當一般 |
| 主力職缺的產品觀察 | **只能由本人提供**（試用心得、觀察）；沒提供就用一般鉤子，不自己研究編造 |

## 2. 結構（250–350 字、6–8 行；欄位上限 2,000）

> 依據：企業端詳細頁**全文展開、純文字、一行約 45–50 字**，位置在履歷本文前、104「符合分析」上方（本人 2026-10-20 截圖）；104 官方建議「簡短精要，約 400–500 字尤佳」。詳見 `104/cover-letter-research.md`。
> - **純文字**：不用 HTML、粗體、Markdown；條列用「‧」開頭＋換行，最多 3 點，每點 1–2 行。
> - 段落之間空一行；不放網址（作品集網址若要放，放最後一行）。
> - 第一句就講職缺名與最相關實績（列表／通知信可能只露開頭，未證實但成本低）。
> - 若 104「符合分析」可能判「不太符合」的項目（年資、產業、學歷）與此職缺相關，可用一句說明落差，不辯解、不誇大。

```text
您好：
應徵【職缺名稱（與 JD 一字不差）】。〔破題：近 10 年產品經理經驗＋與此職缺最相關的一項實績；開頭兩句內要看得到職缺名與核心籌碼〕

‧〔JD 核心需求 1 → 我做過的場景＋行動＋結果〕
‧〔JD 核心需求 2 → 同上〕
‧〔可選第 3 點〕

〔一句鉤子：一般＝產業／商業模式共鳴；主力＝本人提供的產品觀察〕完整經歷與自傳在履歷中，期待有機會進一步說明。

聶崑淮 敬上
```

## 3. 寫法規則

1. **事實只取 library**；數字沿用履歷口徑與限定詞（例：「上線與導流期間」「依公司公開資料」）。沒有的不補、不估。
2. **不照抄 JD 原文、不照抄履歷句子**：用同一事實換角度寫判斷或做法。
3. **缺口不硬補**：JD 要的 Jira、SQL、讀後端程式碼、近母語英文等，推薦信不提、不暗示具備；可改寫相近的真實能力（例：與工程確認後端行為）。
4. 禁用：Spearheaded／主導開發、第一大、案主／業主、AI 套話（「深感契合」「願景高度契合」「在瀏覽貴公司職缺後」）、乞求句（「懇請給予機會」）、軟性形容詞（積極進取、抗壓性強）。
5. 不放電話、Email、地址（履歷已有）。對外不寫 1111 內部系統名、代碼表名。
6. 一封只回應一個職缺；**公司名、職缺名逐字核對 routing.tsv／JD**。

## 4. 產出

- 草稿：`career/letters/104/<code>-<公司>-draft.md`，內容：
  1. 檔頭 HTML 註解：給潤飾者的規則（只改語感、不改事實與數字、保留限定詞、維持 250–350 字、不加 AI 套話）。
  2. 推薦信正文。
  3. 〈對位表〉：每一點對應的 JD 需求 ↔ library 出處（檔名＋節）。
  4. 〈刻意不寫〉：此職缺的已知缺口與處理方式。
- 字數與行數檢查（純文字；以每行 48 字估行數）並寫在檔尾。

## 5. 潤飾後核對與定稿

1. 讀潤飾稿：公司名、職缺名逐字相同；數字、日期、限定詞不變；禁用詞為 0；字數 200–400。
2. 只把語意偏移處回報本人決定；本人同意後存 `career/letters/104/<code>-<公司>.md`（定稿），並在 `career/letters/log.md` 加一列（日期、公司、職缺、語言 zh、檔案、結果〔待填〕）。
3. 新用到的成果句回填 `letters/story-bank.md`；本人新提供的動機或觀察先寫進 `library/`（about-me 或 facts）。
