## 3. 詞彙映射與責任界線

此表用於可改寫內容，保留 LOCK_ENTITIES 的精確字串與責任。先對照 library，再選具體動作；不是任選更強的字。責任動詞限於事實已確認的規劃、協調、定義（使用情境與驗收標準）、設計（流程與規格）、推進、驗收。

| 原詞／句型 | 本人指定替代方向 | 使用界線 |
| --- | --- | --- |
| 透過／藉由／利用 | 以；直接寫已確認動作 | 不因使用工具而新增「導入制度」，也不把背景變成因果 |
| 進行了…的優化 | 規劃流程調整／設計流程與規格／驗收 | 只用 library 確認的範圍；沒有成效數據，不改成壓降或拉升 |
| 跨部門密切溝通協調 | 協調具體單位與事項、推進既定工作 | 不新增拍板權；保留協作關係與實際責任 |
| 解決歷史困難問題 | 寫明既有限制，再寫規劃、協調或驗收內容 | 不把規劃寫成工程工作，也不附贈效能或商業成效 |
| 負責管理／協助推動 | 依 library 選規劃、協調、定義（使用情境與驗收標準）、設計（流程與規格）、推進、驗收 | 不對應到主導、架構、扛下；若「協助」本來就是準確責任，可保留並逐點記錄依據 |
| 透過…進而…最終達成… | 短句／`；`／`｜` | 保留原有因果與先後，不強行挪成果到前面 |

「主導」只允許 library 已確認、且上游同一點已寫出的 Juicy／JustDating 重新上架事件；不自行擴用到定價、AI、群組功能或其他案例。「架構、開發、實作、重構、扛下」不用來描述本人的責任；「開發中」是本輪鎖定狀態，LOCKED 既有的方法名稱仍原樣保留。沒有工程實作，不以更強動詞包裝規劃工作。

## 4. 用詞分兩類

### A. 文體詞：禁用

新版 verifier 的文體詞為：負責日常、聽從、賦能、抓手、閉環、攜手、助力、全方位、深耕、致力於、成功地、圓滿達成、極大地、顯著地、透過、藉由、進行一個、完成了。可改點命中即修正，直接寫已確認的對象、動作與結果；不靠刪事實過關。既有語氣要求也避免「利用」及求職套話。LOCKED 本文不為清文體詞而自行改寫。

### B. 責任詞：不禁，逐點核對並說明

協助、參與、配合、支援、維護不在禁用黑名單；新版 verifier 只對非 LOCKED 點提出警示。每個警示在修改紀錄列明點位、原句／保留句、library 出處與理由，不能只寫「警示可忽略」。若符合真實責任就保留，不得為消警示換成主導；若不符合，改成 library 支持的具體動作並說明。沒有證據時回報，不推定。

本輪兩處保留：尚凡服務承接的「配合行銷導流」、SweetRing 職責的「參與海外市場在地化及支付方案規劃」。逐點來源見本輪 [修改紀錄](../drafts/codex/2026-10-22-r2-polish-handoff.md)。其他三個責任詞未在可改點使用，不需為了列滿清單而新增。

舊 style 中的粗體小標、固定段數、強動詞映射與舊範例數字均不覆蓋本輪上游。

## 5. 英文參數（上游有英文才使用）

- 平實商務英文，第一人稱 I，短句，一句一事，約 25 words 內；美式拼字。
- 固定譯法沿 `career/style/voice-en.md`：job-category codes、acceptance criteria、phased releases、confidence levels。LOCK_ENTITIES 的英文拼法優先，不能順手改成同義詞。
- AI 使用情境與驗收：defined the use cases and acceptance criteria；新版規劃：planned。不得改為 built／developed the model、led the architecture 或 reverse-engineered the codebase。
- 同仁最後判斷的責任不得省掉；不改成 automated the whole process 或 eliminated manual work。
- 禁用 delve、tapestry、seamlessly、leverage、synergy、robust、cutting-edge、proven track record、I am writing to express、I am excited／thrilled to、strategic、passionate、visionary、detail-oriented、results-driven；不用 Spearheaded 包裝責任。
- 不新增 Jira、SQL、工程實作、模型訓練或近母語能力。中文禁詞不機械轉成責任更強的英文動詞。

本輪使用 `d26914a` 原版程式，命令為 `python3 career/scripts/verify_polish.py --local-codex`。不再使用舊版的兩個位置參數。不得修改核對程式、造測試輸入或用樣板冒充上游取得 exit 0。若程式僅在遠端，以 git show 取得原版並在本區暫存執行 `--local-codex`，從 repo 根目錄讀實際本地成品及遠端草稿，記 hash；不得為執行而寫入唯讀的 career/scripts。

這個參數會讀遠端 Claude 草稿；執行前後核對來源 ref 與草稿 blob，來源若變更便重新讀差異，不能將混版結果記為通過。錯誤必須為 0；責任詞警示必須在修改紀錄逐點完成 library 核對，不以警示數量為 0 當目標。

新版程式按 bullet 對齊檢查相似度、實體、LOCKED 列點、文體詞及責任升級，只作第一層核對；不涵蓋非列點的簡介、自傳與專案整段。另核對所有 12 處 LOCKED 完整文字、每點數字及次數、未拆開的原始鎖定詞、責任動詞、因果與語感。相同狀態的重複字串可在同一點去重但不得漏狀態，須記錄，例如 r2「開發中」由兩次保留為一次，其他鎖定詞仍核對逐點字串及次數。

本輪長度已有本人補充：完整事實優先，65–85 字作節奏目標；不把超過 85 字誤報為硬性驗證失敗或假稱每點兩行。其餘硬性核對全部通過才 commit 並推 `codex/resume-writer`；缺草稿或衝突未解都不推。最後由 Claude 讀回重跑核對，並製作 104／PDF；Codex 不因已驗證就宣稱本人已定版或 PDF 已更新。

語感另逐點、再整段閱讀：動詞是否直接帶對象、是否多次把受詞前置、是否反覆補「由我」、列舉是否被逗號切碎、團隊與本人責任是否仍清楚。成果置前不等於後半句必須被動；單點獨立不等於每點重複身分。「由我」不是全域禁詞，也不據此改動 LOCKED；統計只能提示重複，不能代替閱讀。
