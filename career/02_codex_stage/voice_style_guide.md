此表用於可改寫內容，保留 LOCK_ENTITIES 的精確字串與責任。挑選替代詞須符合原來動作，不是任選更強的字。

| 透過／藉由／利用 | 以／基於／導入／改採 | 原本只是使用工具，不因此新增「導入制度」；背景不因此變成因果 |

## 4. 禁用詞與自然替代

下列禁用詞用於可改寫的最終正文檢查；本節表格是指南與反例，不能貼入履歷。本人本輪已明確指定 LOCKED 原樣保留，其中既有禁詞不改；若 NEEDS_POLISH 的鎖定實體內出現禁詞，再逐項回報，不能偷刪。

| 禁用詞／表達 | 改寫方式 |
| --- | --- |
| 協助、參與、配合、支援 | 改寫為上游同一責任範圍的具體動作與對象；不得自動升成主導或架構 |
| 賦能、抓手、閉環、攜手、助力 | 改寫已確認的規劃、規則、檢查、協調或交付內容，不以另一個抽象詞替代 |
| 全方位、深耕、致力於 | 直接寫上游範圍與動作，不加能力自評 |
| 成功地、圓滿達成、極大地 | 直接陳述已知結果，數值、期間與歸因原樣保留 |
| 深感契合、願景高度契合、懇請給予機會 | 信件依已知職缺關聯自然表達，不加乞求句或編造公司觀察 |
| 致力於、深入探討、扮演關鍵角色、無縫接軌、卓越、締造 | 不在下游補浮誇詞或形容詞；改回可核對動作 |

舊中文 style 中的粗體小標、固定四段、強動詞與舊範例數字均不覆蓋本輪上游。用詞可精煉，責任與事實不能跟著放大。

## 5. 英文參數（上游有英文才使用）

- 平實商務英文，第一人稱 I，短句，一句一事，約 25 words 內；美式拼字。
- 固定譯法沿 `career/style/voice-en.md`：job-category codes、acceptance criteria、phased releases、confidence levels。LOCK_ENTITIES 的英文拼法優先，不能順手改成同義詞。
- AI 使用情境與驗收：defined the use cases and acceptance criteria；新版規劃：planned。不得改為 built／developed the model、led the architecture 或 reverse-engineered the codebase。
- 同仁最後判斷的責任不得省掉；不改成 automated the whole process 或 eliminated manual work。
- 禁用 delve、tapestry、seamlessly、leverage、synergy、robust、cutting-edge、proven track record、I am writing to express、I am excited／thrilled to、strategic、passionate、visionary、detail-oriented、results-driven；不用 Spearheaded 包裝責任。
- 不新增 Jira、SQL、工程實作、模型訓練或近母語能力。中文禁詞不機械轉成責任更強的英文動詞。

## 6. 逐區塊操作協議

1. 固定上游提交，記草稿及核對程式 blob hash。草稿必須真實存在且可解析；沒有草稿不產空白或假成品、不用舊 v11.2 充當輸入。
2. 掃描草稿正文的每個狀態區塊，列職位、狀態、原文及鎖定實體；非投遞的實體字典／拓撲／檢查附錄只用來核對，不放進成品。
3. LOCKED 直接原樣複製，除移除其交接標記，不改段落內容、標點或排版。其他未獲改寫標記的內容也不自行重寫。
4. 每次只處理一個職位內的 NEEDS_POLISH 點；完成該區塊後寫入 final_resume.md，處理中的狀態改為 POLISHED。記錄逐點變更、實體與進度，不憑記憶一次重寫全文。
5. 逐點確認鎖定詞、數字、日期、限定、責任及因果不變，再計改寫幅度。以 bullet 內文（不含狀態、`- `）的字元序列計算 `Levenshtein(old, new) / max(len(old), len(new))`（字元插入、刪除及替換的最少次數），每個 NEEDS_POLISH 點須 ≥0.30；這是正規化字元編輯距離，計法在本輪實際修訂前固定用於各點一致核對；不能只靠加標點、換行或填字通過。
6. 每個職位寫入後，核對 LOCKED 未動及下一個待修區塊；全部完成才移除全部交接註解／標記，確認沒有 NEEDS_POLISH、STATUS 或 LOCK_ENTITIES 殘留。`final_resume.md` 只放正文，來源三行與修改紀錄另放交接紀錄，不添加到成品開頭。
