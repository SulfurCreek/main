# 規格：正負推薦簡化格式

> 產出物：[`推薦模型訓練回饋.csv`](推薦模型訓練回饋.csv)（32,248 列）
> 產生腳本：[`../scripts/build_simplified_feedback.py`](../scripts/build_simplified_feedback.py)（可重跑）

## 輸出欄位（僅此 12 欄）

| 欄位 | 內容 |
|---|---|
| `職缺名稱` | 原文照抄 |
| `負向推薦1`~`負向推薦5` | 要壓下去／修正掉的推薦（現行模型第1~5名） |
| `正向推薦1`~`正向推薦5` | 應該推薦的職類與順序（不足5項留白） |
| `優化緣由` | `推薦項目命中率改善` 或 `順序調整` |

## 兩種緣由的定義（正負推薦的取法不同）

以現行模型（20260720）的實際推薦為準。前提：**前5名完全沒命中廠商送出的任一職類**
（前5名若已有命中，代表使用者看得到正確答案，不列入回饋）。

### ■ 推薦項目命中率改善（worst case）

推薦第1~10名**完全沒命中**廠商送出的任一職類。

| | 取法 | 意義 |
|---|---|---|
| 負向推薦 | 模型推薦第1~5名 | 與廠商選擇有落差、沒命中的部分 |
| 正向推薦 | **廠商實際送出的職類**（共識排序） | 讓模型學習與廠商的選擇行為對齊 |

目標：最終產生的推薦能與廠商選擇 sync up。

### ■ 順序調整（enhancement）

前5名沒命中，但廠商送出的職類**出現在第6~10名**。

| | 取法 | 意義 |
|---|---|---|
| 負向推薦 | 模型推薦第1~5名 | 要壓下去的 |
| 正向推薦 | **第6~10名中命中的項目**（依原名次排序） | 要推上前5名的 |

> ⚠️ 此處正向推薦**不是**廠商送出的全部職類，而是「已經在第6~10名、只差沒排進前5」的那些。
> 這是純排序問題，不是命中率問題。

## 合併單位：職缺標題

已驗證**模型輸出 100% 由標題決定**（154,860 個標題中，同標題推薦不一致者 **0** 個）。
同標題的多筆職缺對模型是同一個輸入，只能給一種答案，否則是矛盾訊號。
同標題有多家廠商時，送出職類取聯集、依「幾家廠商送過」由多到少排序（共識優先）。

> 註：符號變體（如 `…（士林）*` 與 `…（士林）**`）是不同字串、對模型是不同輸入，
> 各自成列且緣由可不同，這不算重複。

## 驗收檢查（腳本內建，全數通過）

| # | 檢查 | 結果 |
|---|---|---|
| 1 | 重複職缺標題 | 0 筆 ✅ |
| 2 | 總列數與緣由分布 | 32,248（命中率改善 19,487／順序調整 12,761）✅ |
| 3 | 負向5項全非空、正負零交集、正向1非空 | 32,248/32,248、0、0 ✅ |
| 4 | 順序調整的正向項是否全部來自第6~10名且順序正確 | 不符 0 筆 ✅ |
| 4 | 命中率改善的正向項是否確實完全沒出現在推薦1~10 | 不符 0 筆 ✅ |

## 範例

**順序調整**　`總經理室專員`
```
現行推薦1~10 = 政治相關研究人員, 市場調查／分析人員, 社會學研究人員, 歷史研究人員,
               其他專案管理師, 研究助理, 特別助理, 工商登記服務類人員, 行政人員, 醫院行政管理人員
負向(壓下去) = 政治相關研究人員, 市場調查／分析人員, 社會學研究人員, 歷史研究人員, 其他專案管理師
正向(推上來) = 特別助理                    ← 原本在第7名，廠商有選
```

**推薦項目命中率改善**　`◎市議員助理◎`
```
現行推薦1~10 = 秘書, 行政人員, 代書／地政士, 發包人員, 公家機關相關人員,
               醫院行政管理人員, 法務助理, 都市／交通規劃人員, 估算人員, 工商登記服務類人員
負向(沒命中) = 秘書, 行政人員, 代書／地政士, 發包人員, 公家機關相關人員
正向(廠商選的)= 行政助理, 業務助理, 政治相關研究人員, 市場調查／分析人員, 特別助理
```

## ⚠️ 實作紅線（本資料集曾發生的事故，不得重犯）

1. **不足5項就留白，不准補值。** 歷史版本曾把有問題的模型自己的推薦塞進正解欄位，
   等於把萬用桶偏誤當正解餵回去（詳見
   [`../feedback_訓練標籤污染撤回說明.md`](../feedback_訓練標籤污染撤回說明.md)）。
2. **兩種緣由的正向來源不同，不可混用**：命中率改善取廠商送出職類；順序調整取第6~10名的命中項。
3. **同一個輸入只能有一種緣由**，且判定必須基於單一模型版本的實際狀態。
