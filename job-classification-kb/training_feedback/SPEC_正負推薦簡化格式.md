# 實作規格：正負推薦簡化格式（供其他模型/工程師執行）

> 目的：把 `4_training_rescue_and_reorder_plan.csv`（33,149筆）轉成極簡訓練回饋格式——
> 每筆案例只有「負面推薦5筆＋正向推薦5筆＋優化緣由」，去掉所有中間定義欄位。
> 本文件是**實作規格**，不是產出物；照此規格寫轉換腳本即可。

## 輸出欄位（固定順序）

| 欄位 | 內容 |
|---|---|
| `職缺名稱` | 原文照抄 |
| `負面推薦1`~`負面推薦5` | 錯誤的推薦項（模型不該推的） |
| `正向推薦1`~`正向推薦5` | 正確的推薦項與順序（模型該推的） |
| `優化緣由` | `推薦項目命中率改善` 或 `順序調整`（追蹤用，放表格末端） |

除此之外**不輸出任何其他欄位**（不含情境、問題標記、duty、命中名次等中間定義欄）。

## 轉換規則

來源：`4_training_rescue_and_reorder_plan.csv`（skiprows=1，utf-8-sig）。

### 負面推薦1~5

```
負面推薦1~5 = 現有版本_推薦1 ~ 現有版本_推薦5（照原順序）
```

**為什麼安全（已全量體檢驗證，33,149/33,149 筆通過）**：
- `worst_case_退步案例`：定義即「現有版本推薦1~10與廠商送出100%無交集」→ 前5名必然全錯。
- `enhancement_排序待優化`：定義即「命中名次落在第6~10名」→ 前5名必然不含任何廠商送出職類。

因此兩情境的「現有版本前5名」都保證是純負面項，**直接取前5、不需任何過濾判斷**。
（實作時仍建議加一道 assert：負面5項 ∩ duty0~4 必須為空集合，防來源檔被改壞。）

### 正向推薦1~5

```
正向推薦1~5 = 理想推薦_1 ~ 理想推薦_5（照原順序；不足5項的欄位留白）
```

現行版理想推薦 ＝ 廠商實際送出的 duty0~4（去重、保留原順序、第6欄以後全空），
所以等價於直接取 duty0~4 去重。正向項數分布：1項10,981筆／2項11,663筆／3項9,214筆／
4項302筆／5項989筆——**留白就留白，嚴禁用任何其他來源補滿**（歷史事故的根源就是拿
「有問題的模型輸出」補空欄，見下方教訓）。

### 優化緣由（由 `情境` 欄映射，一對一）

| 來源 `情境` | 輸出 `優化緣由` | 意義 |
|---|---|---|
| `worst_case_退步案例` | `推薦項目命中率改善` | 原本完全沒命中，要把正解救回來 |
| `enhancement_排序待優化` | `順序調整` | 有推到但排第6~10名，要調進前5 |

## 驗收檢查（轉換後必跑）

1. 總列數 ＝ 33,149（14,412筆`推薦項目命中率改善` ＋ 18,737筆`順序調整`）。
2. 每筆的 負面推薦1~5 全部非空，且與該筆正向推薦零交集。
3. 每筆的 正向推薦1 非空；正向推薦只含該職缺廠商實際送出的職類（不得出現任何其他類別）。
4. 抽查 `🎵 卡比音樂工作室｜儲備幹部招募（士林）`：
   - 負面推薦應為音樂演藝類或餐飲類（依情境），正向推薦應為
     `總機／接待／櫃檯人員、編輯／文字類人員、儲備幹部、基層管理幹部、行政人員`。

## 編碼與格式

- utf-8-sig（含BOM，Excel直開不亂碼）、第1行 `#` 註解說明、第2行欄位標題（沿用本資料集慣例）。

## ⚠️ 實作時的紅線（本資料集曾發生的事故，不得重犯）

1. **正向推薦不足5筆就留白，不准用「現有版本推薦」或任何模型輸出補滿**——歷史版本曾把
   有問題的模型自己的推薦塞進理想欄位，等於把萬用桶偏誤當正解餵回去（詳見
   [`../feedback_訓練標籤污染撤回說明.md`](../feedback_訓練標籤污染撤回說明.md)）。
2. **轉換腳本寫完後，驗證要同時涵蓋兩個情境**——上次修 bug 只修了 worst_case 分支、
   漏了 enhancement 同款問題，被抓兩次才修完。
3. 正向推薦的唯一合法來源是**廠商實際送出的 duty0~4**；負面推薦的唯一合法來源是
   **現有版本前5名**。不臆測、不補值。

## 與撤回清單的關係

本格式輸出的「負面推薦」天然涵蓋了撤回需求的主要部分（現有版本前5名本來就是要否定的項目）。
若模型團隊已誤餵歷史污染版本，仍需搭配
[`5_retraction_wrong_ideal_labels.csv`](5_retraction_wrong_ideal_labels.csv) 做完整撤回
（該清單含第6~10名及歷史版本獨有的錯誤配對，範圍比本格式的負面5項更廣）。
