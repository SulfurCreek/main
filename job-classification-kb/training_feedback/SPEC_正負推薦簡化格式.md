# 規格：正負推薦簡化格式

> 產出物：[`推薦模型訓練回饋.csv`](推薦模型訓練回饋.csv)（32,248 列）
> 產生腳本：[`../scripts/build_simplified_feedback.py`](../scripts/build_simplified_feedback.py)（可重跑）

## 輸出欄位（僅此 12 欄）

| 欄位 | 內容 |
|---|---|
| `職缺名稱` | 原文照抄 |
| `負面推薦1`~`負面推薦5` | 模型目前推錯的前5項 |
| `正向推薦1`~`正向推薦5` | 應推薦的正確職類與順序（不足5項留白） |
| `優化緣由` | `推薦項目命中率改善` 或 `順序調整` |

## 三個關鍵設計決定

### 1. 一律以現行模型（20260720）的實際推薦為準

不混用舊模型基準。先前版本曾把「舊模型的評估結果」與「新模型的評估結果」併在同一份檔案，
導致同一筆職缺出現兩列、兩種互相矛盾的緣由，且舊模型那批有 87.7% 早已被新模型修好——
等於叫模型停止推薦它現在根本沒在推的東西。

### 2. 以「職缺標題」為合併單位，一個標題一列一緣由

已驗證**模型輸出 100% 由標題決定**（154,860 個標題中，同標題推薦不一致者 **0** 個）。
因此同標題的多筆職缺對模型而言是同一個輸入，若給兩種不同答案即為矛盾訊號。

同標題有多家廠商送出不同職類時，取**聯集並依「幾家廠商送過」由多到少排序**（共識優先），
取前5項。

> 註：符號變體（如 `…（士林）*` 與 `…（士林）**`）是不同的字串，對模型是不同輸入，
> 因此各自成列、緣由可不同，這不算重複。

### 3. 沿用原本「前5名完全沒命中」的問題定義

若某標題的推薦前5名已含任何一個廠商送過的職類，代表使用者看得到的範圍內已有正確答案，
**不列入回饋**（前端只顯示5筆）。

## 各欄位計算規則

```
負面推薦1~5 = 現行模型推薦第1~5名（照原順序，恆為5項）
正向推薦1~5 = 該標題下廠商送出職類，依共識排序取前5（不足留白）
優化緣由    = 順序調整          ← 正向項出現在推薦第6~10名
              推薦項目命中率改善 ← 正向項完全沒出現在推薦1~10
```

負面與正向**天然零交集**：篩選條件已排除「前5名含廠商送出職類」的標題。

## 驗收檢查（腳本內建，全數通過）

| # | 檢查 | 結果 |
|---|---|---|
| 1 | 重複職缺標題（每標題只能一列一緣由） | 0 筆 ✅ |
| 2 | 總列數與緣由分布 | 32,248（命中率改善 19,492／順序調整 12,756）✅ |
| 3 | 負面5項全非空、正負零交集、正向1非空 | 32,248/32,248、0、0 ✅ |
| 4 | 緣由與現行模型實際狀態逐筆核對 | 不符 0 筆 ✅ |
| 5 | 抽查卡比音樂工作室系列 | 11 個標題各自一列一緣由 ✅ |

## ⚠️ 實作紅線（本資料集曾發生的事故，不得重犯）

1. **正向推薦不足5項就留白，不准用模型輸出補滿。** 歷史版本曾把有問題的模型自己的推薦
   塞進理想欄位，等於把萬用桶偏誤當正解餵回去（詳見
   [`../feedback_訓練標籤污染撤回說明.md`](../feedback_訓練標籤污染撤回說明.md)）。
2. **正向推薦的唯一合法來源是廠商實際送出的職類**；負面推薦的唯一合法來源是
   **現行模型的推薦前5名**。不臆測、不補值。
3. **同一個輸入只能有一種緣由。** 判定必須基於單一模型版本的實際狀態，不可混用不同版本的評估。

## 與撤回清單的關係

若模型團隊已誤餵過歷史污染版本，本檔的「負面推薦」只涵蓋現行模型前5名，
完整撤回仍需搭配 [`5_retraction_wrong_ideal_labels.csv`](5_retraction_wrong_ideal_labels.csv)
（含第6~10名及歷史版本獨有的錯誤配對，共 285,302 個）。
