# E.1 聯絡人才

* User Story: `身為求才廠商，我想要在單一介面集中查看與每位求職者的對話、並直接發出邀約或訊息，以便有效率地管理招募聯繫。`
* Use Case:
  * `廠商於求才進入指定聊天室檢視訊息、發送邀約（詢問意願／面試邀約／錄取通知／感謝函）或一般訊息、封鎖求職者`
  * `求職者於求職主網回覆後，聊天室即時顯示最新訊息。`

## 功能入口

不論從哪一個入口進入，都預設landing在　[1.1 篩選 Tab](#1.1-篩選-Tab)：`一般` Tab

### 4.1 信件列表

於 [信件列表](/uoldEfXhT9KrbGxQJwg4ew) 訊息列表點擊任一對話（by 職缺＋求職者），外開分頁進入該聊天室
![image](https://hackmd.io/_uploads/rywconw-Mg.png)

### 全站右下角浮動icon

* 當廠商登入帳號可以看到的對話有未讀訊息時，常駐顯示紅點提醒
* 點擊浮動icon後，打開浮動訊息列表
  * 於列表點擊`展開`後，進入全螢幕畫面，右方聊天室為空值
  * 於列表點擊`個別聊天室`後，於左側開啟浮動聊天室
  * 於聊天室點擊`展開`後，進入指定聊天室

#### 收到新訊息時行為

收到新訊息時，判斷帳號是否位於信件曾發話過名單、職缺所屬名單、職缺即時通通知帳號

* 符合條件時，當收到求職者新訊息時，以SignalR接收訊號，於漂浮icon即時顯示紅點
* 不符合條件時，在重整畫面後才會顯示紅點

### 權限判斷

透過功能入口或是URL進入時，驗證下列條件

| 權限條件 | 代碼 [求才系統權限代碼表](/B1j3sN-bzx) | 不符合時的處理 |
| :--- | :---: | :--- |
| 帳號需具備「管理履歷、進行人才搜尋」權限（可使用即時通聯繫人才） | `代碼51` | URL 進入時顯示無權限 alert modal，點擊後返回首頁 |
| 對話職缺非帳號可管理範圍（帳號權限） | `10+26`／`10+27`| 顯示無權限 alert modal，點擊後返回前一頁 |

### 資料載入

* 進入畫面時
  * 取得根據條件取得每個tab的現有訊息數量`get-by-condition-count`，[1.1 篩選 Tab](#-1.1 篩選 Tab)（回傳欄位對照見 [REF 對照庫](/uS9yE837SYedY9hQFneb6Q) §4.3）
  * 依登入廠商帳號，`get-by-condition` 載入該帳號可見職缺之相關聯且90天內有訊息的對話於[1.2 左側訊息列表](#-1.2 左側訊息列表)，`by職缺 by求職者` 各成一筆聊天室
  * 透過URL指向的對話，於左側列表呈現 `selected` 狀態，排序為列表第一位（位於置頂的上方），右側聊天室`get-details`載入該則對話90天內訊息。

##### 查看履歷

* 點擊後，另開分頁打開求職者履歷詳細頁
  * 串接現版即時通的查看履歷API，帶`rNo`、`resumeGUID`、`eNo`、`role`等資料
  * 備註：需扣點廠商可能會有問題，第二階段才會實作扣點機制

:::spoiler

**現版機制**

* 觸發點：`handleResumeView()`，由 `#eChat_ResumeLink`（查看履歷按鈕）與 `.message_avatar`（訊息列表大頭貼）共用觸發
* 資料預載（`SetResumeLink()`，廠商**切換聊天室當下**即執行，非點擊查看履歷當下才打）：
  * AJAX：`POST /eChat_2022/eChatHandler.ashx { kind: 4, tNo, eNo }`
  * 回傳：`ResumeGuid`、`tNo`、`eNo`、`rNo`、`SnapshotGuid`、`CanChat`、`Img`
  * **URL 組裝邏輯**（前端用回傳資料現組，非後端直接給完整網址）：

      ```js
      let ResumeLink = `/lightBox/ResumeDetail.aspx?Row=${data.ResumeGuid}&tNo=${data.tNo}&eNo=${data.eNo}`;
      if (data.rNo > 0) ResumeLink += `&rNo=${data.rNo}`;
      if (data.SnapshotGuid.length > 0) ResumeLink += `&Snap=${data.SnapshotGuid}`;
      ResumeLink += '&ref=eChatUC&vrS=15';
      ```
  * 綁定規則：`ResumeGuid` 非空 **且** `CanChat == 1` → 按鈕標題「查看完整履歷」，`data-resumelink` 存上述組好的網址；否則按鈕標題「查看個人資料」、`data-resumelink` 留空（點擊後走情境 A 基本資料）
  * 同時觸發 `SetResumeReaded(ResumeGuid, rNo)` → `POST eChatHandler.ashx { kind: 7, tNo, rNo, tGuid }`，通知後端「企業已看過此人履歷」
  * 點擊當下判斷（純讀取已綁定的 `data-resumelink`／`data-msg`，點擊當下**不再另打 API**）：

    | 情境 | 條件 | 動作 |
    | :--- | :--- | :--- |
    | A. 無履歷 | `resumelink` 空 且 `msg` 空 | Lightbox 開 `/lightBox/ResumeBasic.aspx?eChat=1&tNo={tNo}`（顯示基本資料，800×280） |
    | B. 有履歷 | `msg` 空（代表有 `resumelink`） | `window.open(resumelink)` 另開分頁 |
    | C. 狀態異常 | `msg` 非空（如已封鎖／停權） | `msgShow(msg)` 彈出提示文字，不開履歷 |

:::spoiler 現版特定廠商會發生，但扣點機制（第二階段）之後才會補上，先顯示錯誤訊息即可

> 來源：現版 `eChat_2022` 前端 JS 邏輯分析，記錄現況供之後在新版聊天室重新實作時參考，非本次新規格定案。僅發生在企業尚無權限對此求職者聊天／看履歷的情況（`#eChat_Pay` 按鈕，出現在輸入框遮罩內），不是每次查看履歷都會扣點。

1. 依現況分兩種確認文案：求職者履歷關閉或無履歷（`resumelink` 空）→「此求職者履歷關閉中或是無履歷，是否要消費點數開啟即時通訊聯繫？」；有履歷但需付費（`ResumeGuid` 非空）→「您所選取的求職者需要消費點數，是否要消費點數開啟即時通訊聯繫？」
2. 使用者按「確定」→ `POST eChatHandler.ashx { kind: 11, tNo, tRole: eRole, rNo, tGid: ResumeGuid }`
3. 回傳 `{ isPaid, msgStr }`：`isPaid == true` → 扣點成功，解除輸入框遮罩、允許交談；否則顯示 `msgStr` 錯誤訊息（未扣成功，遮罩維持）

#### 1.3.5 text area與送出按鈕

* `輸入訊息` 輸入框，供廠商輸入一般訊息，最多可輸入1200字
* 點擊 `傳送` 後：
  * 畫面即時更新：將內容顯示為一則新的一般訊息泡泡
  * 呼叫一般訊息API寫入訊息，並同步整併資料（`update-chatlog`）
  * 求職者若在線上，即時收到 SignalR 通知／App 推播；不在線上則於重新整理或重進聊天室時看到新訊息
  * 通知信**加入寄信排程**（非即時寄出，處理很快但非馬上送出）

> 完整同步機制與排程細節見 [REF 對照庫](/uS9yE837SYedY9hQFneb6Q) §2.4／§8
