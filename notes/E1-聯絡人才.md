# E.1 聯絡人才

* User Story: `身為求才廠商，我想要在單一介面集中查看與每位求職者的對話、並直接發出邀約或訊息，以便有效率地管理招募聯繫。`
* Use Case:
  * `廠商於求才進入指定聊天室檢視訊息、發送邀約（詢問意願／面試邀約／錄取通知／感謝函）或一般訊息、封鎖求職者`
  * `求職者於求職主網回覆後，聊天室即時顯示最新訊息。`

## 初始化

### 進入路徑

* [信件列表](/uoldEfXhT9KrbGxQJwg4ew) 訊息列表點擊任一對話（by 職缺＋求職者），外開分頁進入該聊天室
![image](https://hackmd.io/_uploads/rywconw-Mg.png)
* 右下角`即時通` 浮動面板，點擊展開後，進入指定聊天室<br><div style="max-width:500px">![image](https://hackmd.io/_uploads/r1AAjnvZMg.png)</div>
* 預設landing在[1.1 篩選 Tab](#1.1-篩選-Tab)：`一般` Tab

### 權限判斷

透過功能入口或是URL進入時，驗證下列條件

| 權限條件 | 代碼 [求才系統權限代碼表](/B1j3sN-bzx) | 不符合時的處理 |
| :--- | :---: | :--- |
| 帳號需具備「管理履歷、進行人才搜尋」權限（可使用即時通聯繫人才） | `代碼51` | URL 進入時顯示無權限 alert modal，點擊後返回首頁 |
| 對話職缺非帳號可管理範圍（帳號權限） | `10+26`／`10+27`| 顯示無權限 alert modal，點擊後返回前一頁 |
|履歷狀態異常（求職者履歷狀態） |待補 | 顯示alert modal，點擊後關閉分頁 |

### 資料載入

* 進入畫面時：
  * 依登入廠商帳號，載入該帳號可見職缺之相關聯且90天內有訊息的對話於列表，`by職缺 by求職者` 各成一筆聊天室
  * 透過URL指向的對話，於左側列表呈現 `selected` 狀態，右側聊天室載入該則對話90天內訊息。
* 相關 API／資料表名稱：
  * 列表載入：`GET /api/v1/external/echat/get-echat-mail-logs`（query：`organNo`、`talentNo`、`empNo`，可選帶起始日／結束日；header `X-CUSTOM-API-KEY`）→ 回傳每筆對話摘要（`rNo`、`organNo`、`organName`、`talentNo`、`tName`、`tRole`、`resumeNo`、`resumeGuid`、`snapshotGuid`、`empNo`、`empName`、`eRole`、`uNos`、`oDelFlag`、`tDelFlag`、`dateIn`、`lastMsg`）
  * 右側聊天室訊息載入：`GET /api/v1/external/echat/get-detail/{infoNo}`（`infoNo` = 上述列表回傳的 `rNo`；header `X-CUSTOM-API-KEY`）→ 回傳該筆對話完整資料＋ `oJsonB`／`tJsonB`（廠商／求職者對話訊息明細陣列）
    | 狀態 | 觸發條件 | 畫面呈現 |
    | :--- | :--- | :--- |
    | 載入中 | 進入頁面結果回傳前 | 整頁顯示Loading動畫 |
    | 有資料 | 取得回傳資料 | 依資料渲染`1.2訊息列表`與`1.3聊天室`|
    | 無資料 | 無任何資料 | 顯示 [Empty State](#1-聯絡人才)|
    | 錯誤 | 列表 API 失敗 | 顯示錯誤 toast（文案 `待補`） |

### 1.3 聊天室

* 進入特定聊天室時，載入該對話的90天內訊息與對話資料
* 由左側聊天列表點選某筆聊天室後，右側面板載入該「職缺 × 求職者」的對話資料：`1.3.1對話資訊`、`1.3.2 操作選單`、`1.3.3 訊息顯示區`、`1.3.4 發送新邀約按鈕`、`1.3.5 Text Area與按鈕`。
* 相關 API：`GET /api/v1/external/echat/get-detail/{infoNo}`（`infoNo` = 該對話的 `rNo`）→ 取得 `oJsonB`／`tJsonB` 訊息明細，渲染 `1.3.3 訊息顯示區`
* <font style="color:red">**即時更新（接收新訊息）**：收到 SignalR `onSignal` 通知時，通知內容即包含可打「取得全部對話 API」（目前僅此 1 支，求才端即 `get-detail/{infoNo}`）所需的參數：</font>
  * <font style="color:red">正常對話情況會帶 `updateId`（異動編號）更新——前端可據此判斷哪些資料已存在資料庫中、哪些還沒</font>

## API 欄位詳細描述

本節為 `GET /api/v1/external/echat/get-detail/{infoNo}`（詳見 [資料載入](#資料載入)、[1.3 聊天室](#1.3-聊天室)）回傳資料的完整欄位說明，含回傳物件本身欄位，以及 `oJsonB`／`tJsonB`（訊息明細陣列）內每一筆元素的欄位。

### get-detail/{infoNo} 回傳欄位

| 參數名稱 | 型別 | 說明 |
| :--- | :--- | :--- |
| `rNo` | int | 流水號 (PK) |
| `organNo` | int | 廠商編號 |
| `organName` | string | 廠商名稱 |
| `talentNo` | int | 人才編號 |
| `tName` | string | 人才姓名 |
| `tRole` | int | 人才角色 |
| `resumeNo` | int | 履歷編號 |
| `resumeGuid` | string | 履歷 GUID |
| `snapshotGuid` | string | 快照 GUID |
| `empNo` | int | 職缺編號 |
| `empName` | string | 職缺名稱 |
| `eRole` | int | 職缺角色 |
| `uNos` | string | 使用者編號集合 |
| `oJsonB` | json | 廠商視角對話紀錄 (JSON 物件，陣列元素欄位見下方) |
| `tJsonB` | json | 求職者視角對話紀錄 (JSON 物件，陣列元素欄位見下方) |
| `oDelFlag` | bool | 廠商刪除標記 |
| `tDelFlag` | bool | 求職者刪除標記 |
| `dateSend` | datetime | 建立/更新時間 |

### oJsonB／tJsonB 訊息明細欄位（陣列元素）
