## 1. 目標

系統內「關鍵字搜尋」的輸入符號規則改版。要處理的是**使用者過去輸入、已存在系統裡的舊關鍵字資料**：

資料處理工具：使用者會用 Google Sheet 的 Claude extension 執行（所以需要一份可直接貼進去的指令；**指令尚未產生**，見第 8 節）。

## 2. 規則變更（舊 → 新）

來源：HackMD「3.2.2 簡易搜尋」v0.0.4（shortId `BkMNTH_Pfe`，https://hackmd.io/@1111-jobdocs/BkMNTH_Pfe）〈關鍵字input欄位優化〉。適用簡易搜尋、進階搜尋的關鍵字欄位，搜尋引擎為碩網 Solr。

| 意思 | 舊輸入符號 | 新輸入符號 | 範例（新） |
| :--- | :---: | :---: | :--- |
| 符合任一（OR） | `\|` | 半形空格 | `網站企劃 活動企劃` |
| 同時符合（AND） | `&` | `+`（半形加號） | `網站企劃+活動企劃` |
| 排除（AND NOT） | `!` | `!`（不變） | `工程師!行政` |

[文件] 新 tooltip 文字：「空格＝符合任一」「`+`＝同時符合」「`!`＝排除」；使用限制「最多 6 組關鍵字，每組 50 字以內」。
[文件] 舊提示文字為「可輸入多組關鍵字，以空格、+、!分隔，最多 50 字」（舊限制看起來是**總字數** 50，新限制是 6 組、每組 50 字；兩者定義不同，見第 7 節）。
[文件] 新增紅字提示：「建議使用【半形空格】分隔關鍵字，找到更多求職者！如【工程師 設計師】」。

「舊資料裡空格」的語意：[使用者] 舊規則下空格**沒有特殊規則，算在關鍵字裡面**（例如 `Hewlett Packard` 是一個詞）。

## 3. 後端實際行為（最重要，推翻了討論早期的假設）

[工程師] 讀 code 後的回覆：

- 拆解：`WiseSearch.cs:3875` `ParseKeywordTokens`。第一個詞是起始基準；後面的詞依前面的符號帶運算子：空格→`|`（OR）、`+`→`&`（AND）、`!`→AND NOT。例：`A B+C!D` → `["A", "|B", "&C", "!D"]`。
- 組語法：`WiseSearch.cs:3778` `oKeyWord2Sql`。每個關鍵字**平鋪串接**，**沒有自動加括號**：`(A) OR (B) AND (C) AND NOT (D)`。
- Lucene/Solr 運算子優先順序：**NOT > AND > OR**。所以上例實際是 `A OR (B AND C AND NOT D)`。
- 結論：
  1. `A B+C` ＝ A **或**（B 且 C），**不是**（A 或 B）且 C。
  2. `+C`、`!D` 只約束**緊鄰的前一個詞**所在的 AND 串，不會約束到前面的 OR 分支。
  3. 介面與後端**不支援括號**。要表達「（A 或 B）且 C 且排除 D」，必須用分配律展開：`A+C!D B+C!D`（每個 OR 分支各自帶 `+C!D`）。
- [使用者] 工程師確認：舊的 `|`、`&` 與新規則**走同一段程式**，只是輸入符號不同。因此**只換符號、不改結構，行為與現在完全相同**（包含混用時的優先順序）。

### 3.1 已被推翻的早期假設

討論早期使用者與助理曾假設 `A B+C`＝（A 或 B）且 C，並據此推論 `A+B C!D` 的結果。**這個假設是錯的**，以第 3 節為準。

### 3.2 範例真值表（以 `A B+C!D` 為例，實際＝ A 或（B 且 C 且非 D））

| 履歷內容 | 使用者直覺（A 或 B）且 C 且非 D | 實際 |
| :--- | :---: | :---: |
| 只有 A | 不符合 | 符合 |
| 有 A 且有 D | 不符合 | 符合 |
| 有 B、有 C、沒有 D | 符合 | 符合 |
| 只有 B | 不符合 | 不符合 |

### 3.3 展開的限制（尚待工程師確認）

分配律展開會讓共用條件重複出現，字數與「組數」變多。例：`艾克爾&廠務|空調|消防|水電` 想表達「艾克爾 且（廠務 或 空調 或 消防 或 水電）」，展開為 `廠務+艾克爾 空調+艾克爾 消防+艾克爾 水電+艾克爾`。
**待確認：「最多 6 組」的「組」是算空格分開的分支數（上例＝4），還是算所有詞的個數（上例＝8）？**

## 6. 轉換演算法草稿（機械取代部分，[建議]，未驗證）

順序很重要，避免互相污染：

1. 保護區：先標記 `C++`、`C#`、`.Net` 這類含 `+`、`#`、`.` 的字面關鍵字，不當運算符處理。
2. 正規化：全形 `｜ ＆ ！ ＋` → 半形；去掉符號前後空格。
3. 去包住符號：`〝 〞 「 」 『 』 “ ” 【 】 [ ]` 等只包住詞時去掉。
4. 其他分隔符（`, ， 、 ; ；`，以及中文之間的 `/` `.`）→ 空格。
5. 英文運算詞 `or/OR` → 空格、`AND` → `+`、`NOT` → `!`。
6. 核心取代：`|` → 空格、`&` → `+`、`!` 不變。
7. 檢查：邊緣符號、連續符號、括號、組數（>6）、每組長度（>50）、非關鍵字特徵 → 歸第 3 類（或依規則歸第 2 類）。
8. 不覆蓋原值；輸出新欄位＋分類欄＋理由欄＋旗標欄（「含空格，語意改變」、「疑似縮寫」、「疑似非關鍵字」）。
